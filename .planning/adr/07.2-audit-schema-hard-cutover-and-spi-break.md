# ADR 07.2 — Audit Schema Hard Cutover + AuditListener SPI Breaking Change

**Date:** 2026-04-24
**Status:** Accepted (locked by Phase 7.2 CONTEXT D-03 + D-06)
**Phase:** 7.2 — Redesign Audit Schema as Tree-Lite (PARENT_ID)

## Context

Phase 4 shipped `AI_AGENT_TOOL_CALL_AUDIT` as a flat table with `KIND` +
`PHASE = PRE/POST` discriminators and a NOT-NULL `TOOL_NAME` (forcing a
`<chat>` sentinel for CHAT rows). Phase 7.2 replaces this with a self-
referential `PARENT_ID` FK ("tree-lite"): one chat turn = one root row
(`KIND = CHAT`, `PARENT_ID = null`), TOOL / RETRIEVAL events as children.

## Decision 1 — Hard Cutover (No Backfill)

The new changelog `090-ai-audit-event.xml` DROPS `AI_AGENT_TOOL_CALL_AUDIT`
and CREATES `AI_AGENT_AUDIT_EVENT` in the same transaction. No data is
preserved.

**Rationale:** Pre-v1 codebase. STATE.md confirms audit rows to date are
dev-only. Backfill (group-by-runId + synthesize root from PRE/POST pair)
would cost a full planning cycle with no consumer value.

**Impact for v1 consumers:** There is NO upgrade path from pre-v1 audit
data. Anyone who adopted a pre-v1 build and cares about historical audit
rows must export before upgrading.

## Decision 2 — AuditListener SPI Breaking Change

`AuditListener.onToolCallAudited(UUID auditId)` is REMOVED (not deprecated)
and replaced with `AuditListener.onEventAudited(UUID auditId, String kind)`.
`AuditListenerDispatcher.dispatchToolCallAudited` → `dispatchEventAudited`.

**Kind values:** `CHAT`, `TOOL`, `RETRIEVAL` (defined as `String` constants
on `com.vn.agent.spi.AuditKind` — not an enum, so hosts can define their
own kinds without SPI change).

**In-tree callers updated in Phase 7.2 (exhaustive):**
1. `AuditListenerDispatcher`
2. `AuditWriter` fan-out call sites
3. `SpiDefaultsAutoConfiguration` (no-op bean)
4. `FoundationsBootSmokeTest` line 264
5. `AuditListenerDispatcherTest`
6. `AuditListener` SPI itself

**Rationale:** Solo codebase, no external SPI consumers — break is cheap.
Fan-out coverage was previously tool-only; generalizing to all kinds
(D-05) requires a kind parameter on the listener method. Deprecation
bridge would mean two code paths for the lifetime of deprecation with
zero benefit.

## Migration Note for Host Applications

Hosts that implement a custom `AuditListener` must:
1. Rename `onToolCallAudited(UUID)` → `onEventAudited(UUID, String)`.
2. Branch on kind if per-kind behavior is needed:
   `if (AuditKind.TOOL.equals(kind)) { ... }`.
3. Accept that additional kinds (`GUARDRAIL`, `RATE_LIMIT`, ...) may
   arrive in future releases — listeners MUST be kind-tolerant.
