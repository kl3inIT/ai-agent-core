# Quick Task 260427-9ci: Read-only Baseline Context UI

Add a small admin diagnostic screen that lets operators inspect the exact baseline prompt block currently generated for the logged-in user's Jmix security context.

This is not part of Phase 9 UAT scope today; it is a follow-up quick task requested during UAT because the baseline is otherwise only visible through tests and captured prompts.

## Context

Current baseline generation path:

- `BaselineContextProvider.renderAsText(UUID conversationId)` returns newline-joined `agent.*` context.
- `DefaultChatServiceImpl` prepends that text to the system prompt in both blocking and streaming chat paths.
- No current Flow UI view renders this block directly.

Relevant verified references:

- Jmix Context7 confirms custom views use `StandardView` with `@ViewController` and `@ViewDescriptor`.
- Jmix Context7 confirms button click handlers use `@Subscribe("buttonId")` with `ClickEvent<Button>`.
- Jmix Context7 confirms access is granted with `@ViewPolicy` and `@MenuPolicy` on resource roles.
- Local `jmix-views` skill confirms XML descriptor + Java controller + menu entry + all-locale messages are required.

## Tasks

### Task 1: Add read-only BaselineContextView

Files:

- `ai-agent/ai-agent/src/main/java/com/vn/agent/view/diagnostics/BaselineContextView.java`
- `ai-agent/ai-agent/src/main/resources/com/vn/agent/view/diagnostics/baseline-context-view.xml`

Action:

- Create `BaselineContextView extends StandardView`.
- Annotate with:
  - `@Route(value = "ai-agent/baseline-context", layout = DefaultMainViewParent.class)`
  - `@ViewController("AiAgent_BaselineContext")`
  - `@ViewDescriptor("baseline-context-view.xml")`
- Inject `BaselineContextProvider`.
- Use `@ViewComponent` for the read-only preview component and any status field.
- Render on `BeforeShowEvent` or `ReadyEvent` using `baselineContextProvider.renderAsText(conversationIdOrNull)`.
- Add refresh button handler with `@Subscribe("refreshButton")`.
- Optional: accept `conversationId` query parameter and pass it to `renderAsText(...)`; invalid UUID should clear to null and show a generic warning.
- The preview component must be read-only. Prefer `codeEditor readOnly="true"` for monospaced prompt text; `textArea readOnly="true"` is acceptable if CodeEditor causes dependency issues.
- No business logic beyond calling the provider and setting component values.

Verification:

- View opens and shows the same `agent.*` text shape produced by `BaselineContextProvider.renderAsText(...)`.
- Refresh button re-renders the preview under the current user/security context.
- There is no save action and no editable baseline component.

### Task 2: Wire menu, security, and messages

Files:

- `ai-agent/ai-agent/src/main/resources/com/vn/agent/menu.xml`
- `ai-agent/ai-agent/src/main/java/com/vn/agent/security/AiAgentAdminRole.java`
- `ai-agent/ai-agent/src/main/resources/com/vn/agent/messages_en.properties`
- `ai-agent/ai-agent/src/main/resources/com/vn/agent/messages_vi.properties`

Action:

- Add menu item under the existing `AI` menu:
  - id: `aiAgent.baselineContext`
  - view: `AiAgent_BaselineContext`
  - title key: `com.vn.agent/menu.baselineContext`
- Add admin role policies:
  - `@MenuPolicy(menuIds = "... aiAgent.baselineContext ...")`
  - `@ViewPolicy(viewIds = "... AiAgent_BaselineContext ...")`
- Do not grant this view/menu to `AiAgentUserRole`.
- Add all visible labels to both locale bundles:
  - menu label
  - view title
  - refresh button
  - preview label
  - optional generated-at/status label
  - optional invalid-conversation warning

Verification:

- Admin role can reach the view through the AI menu.
- User role does not receive the menu/view policy.
- No hardcoded UI text remains in XML or controller.

Files:

## Out of Scope

- Editing baseline values.
- Persisting baseline snapshots.
- Showing historical prompts/audit records; those stay in the audit/conversation views.
- Adding a non-admin user-facing diagnostic surface.
- Fixing Phase 9 verification blockers; this task is only the read-only observability UI.
