dth-crm ↔ ai-agent addon — chọn cách tích hợp / dev workflow

Mục tiêu: dùng dth-crm làm host để phát triển & kiểm thử addon, thay cho jmix-app demo.

Thực trạng đã khảo sát: Kiến trúc đã đúng chuẩn addon. ai-agent-core = project addon (publish com.vn:ai-agent-starter:1.1.1-SNAPSHOT ra Nexus). dth-crm = app thật (Jmix 2.8.1), đã wire đầy đủ (agentstore+pgvector, Spring AI/OpenRouter, catalog model, prompt tiếng Việt) và đã consume addon + bắc cầu bằng CrmReportToolContributor (SPI ToolContributor). dth-crm dựng trên jmix-crm sample (com.company.crm.*, 218 file). Coords addon khớp com.vn:ai-agent-starter ⇒ rất hợp composite build.

A. Composite build Khuyến nghị

dth-crm/settings.gradle thêm includeBuild('../ai-agent-core/ai-agent'). Gradle tự thay dependency Nexus bằng source addon local.

  • Sửa addon → chạy dth-crm → áp dụng ngay, KHÔNG publish
  • 0 dòng port; addon vẫn release độc lập
  • Prod/CI vẫn lấy từ Nexus (bỏ includeBuild là xong)
  • jmix-app giữ nguyên làm test host của addon
  • 2 repo song song; cần cùng Jmix/Spring AI version (đang khớp)
Vòng lặp: tức thìRủi ro: thấpPort: 0

B. Publish loop Status quo

Giữ nguyên: publishToMavenLocal / push snapshot Nexus, dth-crm changing=true kéo về.

  • Cô lập tuyệt đối; giống prod
  • Không đổi gì cấu hình
  • Mỗi thay đổi phải publish lại → chậm
  • Dễ lệch version cache, khó debug
Vòng lặp: chậmRủi ro: thấpPort: 0

C. Port dth-crm vào đây Không nên

Bê dth-crm thành module host trong composite ai-agent-core, bỏ jmix-app.

  • 1 repo duy nhất khi dev
  • Nhốt sản phẩm thật vào repo addon → mất tính phân phối
  • Trộn 2 lịch sử git, 2 vòng đời release
  • Mất jmix-app (test host tự chứa của addon)
Vòng lặp: tức thìRủi ro: caoPort: rất lớn

D. Vendor addon vào dth-crm Không nên

Copy source addon (com.vn.agent) thẳng vào dth-crm, bỏ dependency.

  • Không cần build phụ
  • Mất hẳn tính tái sử dụng — addon thành code riêng của 1 app
  • Vá lỗi/tính năng không quay về addon được
  • Trái định vị "agent harness tái sử dụng"
