## Summary

Deep review covered all listed files plus cross-file call-chain validation for stream/cancel behavior against `ChatService.stream(...)` and `CancellationRegistry`.

Primary concerns:
1. `Stop` is not effective during the normal pre-final streaming window.
2. Streamed error events render raw i18n keys to end users.
3. Locale bundles are missing a key that is emitted by streaming error mapping.
4. Current stop tests are static-source sentinels and miss runtime behavior regressions.

## Warnings

### WR-01: Stop action is a no-op until stream completion

**File:** `D:\DTH\ai-agent-core\ai-agent\ai-agent\src\main\java\com\vn\agent\view\chat\fragment\ChatPanelFragment.java:121-126`  
**Issue:** `onStopButtonClick()` only cancels when `activeRunId != null`, but `activeRunId` is assigned only when `StreamingEvent.Final` arrives (`ChatPanelFragment.java:215-216`). In the normal active-stream window, users can click Stop and nothing is cancelled. This also means `startNewChat()` / `setConversationId()` mid-stream may fail to stop the in-flight stream when `activeRunId` is still null.  
**Fix:**
```java
@Subscribe("stopButton")
public void onStopButtonClick(final ClickEvent<Button> event) {
    if (activeRunId != null) {
        cancellationRegistry.cancel(activeRunId);
        return;
    }
    Disposable d = activeStream;
    if (d != null && !d.isDisposed()) {
        d.dispose(); // fallback when runId not yet available
        finishStreamInternal();
    }
}
```

### WR-02: Stream error messages are shown as raw message keys

**File:** `D:\DTH\ai-agent-core\ai-agent\ai-agent\src\main\java\com\vn\agent\view\chat\fragment\StreamEventRenderer.java:98-101`  
**Issue:** `StreamingEvent.Error` rendering outputs `err.messageKey()` directly, so users see keys like `ai-agent.guard.rate-limit-exceeded` instead of localized text. This is visible because streaming errors are emitted as events (not exceptions) and rendered inline.  
**Fix:**
```java
case StreamingEvent.Error err -> {
    String errorLabel = labels.getOrDefault("chatView.stream.error", "error");
    String errorText = labels.getOrDefault(err.messageKey(), err.messageKey());
    yield "\n\n---\n**%s:** %s".formatted(errorLabel, errorText);
}
```
Also add relevant error-key entries into the labels map in `ChatPanelFragment.resolveLabels()`.

### WR-03: Missing locale key for conversation-not-found streaming error

**File:** `D:\DTH\ai-agent-core\ai-agent\ai-agent\src\main\resources\com\vn\agent\messages_en.properties:133-137`  
**Issue:** Streaming error mapping emits `chatView.error.conversationNotFound`, but this key is absent in both locale files. Even after renderer localization is fixed, this specific path still falls back to raw key text.  
**Fix:**
```properties
# messages_en.properties
chatView.error.conversationNotFound=Conversation not found or no longer accessible.
```
```properties
# messages_vi.properties
chatView.error.conversationNotFound=Không tìm thấy cuộc hội thoại hoặc bạn không còn quyền truy cập.
```

## Info

### IN-01: Stop test uses source-text heuristics and misses runtime stop behavior

**File:** `D:\DTH\ai-agent-core\ai-agent\ai-agent\src\test\java\com\vn\agent\view\chat\ChatViewStopTest.java:51-74`  
**Issue:** The test validates string occurrences in source code (`activeStream.dispose()` / `cancellationRegistry.cancel(...)`) rather than observable runtime behavior. This allowed the current stop no-op regression to pass.  
**Fix:** Add a behavior-focused unit/integration test for Stop during an active stream before Final (or an integration test in a module with UI harness) and assert stream disposal/cancellation side effects.
