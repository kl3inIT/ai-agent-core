# Phase 7.1 Plan 02: Pure StreamEventRenderer Helper Summary

Extract the event → markdown mapping into a pure static helper (`StreamEventRenderer.renderStreamEvent`) with a 10-method JUnit 5 contract test, so Plan 07.1-03's Fragment rewrite can focus exclusively on Vaadin wiring. The renderer has zero Vaadin and zero Spring imports — it takes a pre-resolved `Map<String, String>` of i18n labels from the caller and returns a markdown string.

## Public Surface (for Plan 07.1-03 to import)

```java
package com.vn.agent.view.chat.fragment;

public final class StreamEventRenderer {

    // Per-turn holder; Plan 03 allocates a fresh instance on each submit.
    public static final class CitationState {
        public boolean consumeFirst();
    }

    public static String renderStreamEvent(StreamingEvent event,
                                           Map<String, String> labels,
                                           CitationState citationState);
}
```

| `chatView.stream.sources`               | Citation first-of-turn    | "Sources" / "Nguồn tham khảo"     |
| `chatView.stream.outcome.SUCCESS`       | ToolResult outcome label  | Upper-case enum-name suffix       |
| `chatView.stream.outcome.BLOCKED`       | ToolResult outcome label  | Upper-case enum-name suffix       |

| `chatView.stream.outcome.FLAGGED`       | ToolResult outcome label  | Upper-case enum-name suffix       |

All six renderer-consumed keys were verified to exist in `messages_en.properties` at lines 143–151 (seeded by Plan 07.1-01).

## Event → Markdown Mapping (locked under unit test)

| StreamingEvent variant           | Renderer output                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------ |
| `Content(markdownChunk)`         | `markdownChunk` verbatim; `null` → `""`                                                          |
| `Content("<script>…</script>")`  | Passes through verbatim server-side; Vaadin markdown sanitises on render (RESEARCH §Security A2) |
| `ToolCall(_, name, argsJson)`    | `"\n\n**{name}**: {shortArgs}"`                                                                  |
| `ToolResult(_, summary, outcome)`| `"  \n_{outcomeLabel} — {summary}_\n\n---\n"` with outcome label via labels map                  |
| `Citation(idx, docId, _)` first  | Prepends `"\n\n---\n**Sources**"` then bullet `"- [docId](/ai-agent/knowledge?documentId=docId)"` |
| `Citation(idx, docId, _)` later  | Bullet only (no header); CitationState.consumeFirst() drives the gate                            |
| `Citation(idx, null, _)`         | A5 null-guard: emits `"\n- source"` plain bullet (no href, no NPE)                               |
| `Error(messageKey, params)`      | `"\n\n---\n**{errorLabel}:** {messageKey}"` — KEY forwarded for the Fragment to resolve          |
| `Final(_, _, _, _)`              | `""` (v1 per RESEARCH Open Question 2)                                                           |

`shortArgs` collapses whitespace and truncates to 80 chars (77 + `...`).

## Deep-link Format (A-03 correction)

Citation links use the query parameter **`documentId=`** (not `docId=`) to match the `KnowledgeBaseView` route contract established by Plan 07-06. The test `citation_firstOfTurn_emitsSourcesHeader_andDeepLink` hard-asserts on the literal `/ai-agent/knowledge?documentId=<uuid>` substring so this cannot silently regress.
