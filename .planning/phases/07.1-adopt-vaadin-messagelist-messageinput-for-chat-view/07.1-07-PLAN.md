<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM → MessageList markdown render (client-side) | Untrusted model-generated markdown could contain `<script>` / `<iframe>` / `javascript:` URLs |
| User URL bar → ChatView conversationId query-param | Untrusted UUID string; ownership check must not leak existence of other users' conversations |
| Stop button click → CancellationRegistry | Spurious or replayed runIds |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7.1-01 | Tampering / XSS | MessageList.setMarkdown(true) rendering LLM output | mitigate | Client-side markdown parser (Vaadin) is expected to escape raw HTML/JS — XSS passthrough smoke in RenderStreamEventTest (Plan 02) asserts server-side passes raw markdown through verbatim; Vaadin client escapes (§A2 assumption log, RESEARCH Security Domain) |
| T-7.1-02 | Information Disclosure | conversationId enumeration via URL guessing | mitigate | ConversationGateway.loadOrCreate enforces ownership (Phase 4 D-09 opacity); ChatView.beforeEnter catches both `ConversationNotFoundException` and `IllegalArgumentException` emitting identical `chatView.error.generic` Notification — no information leak about existence |
| T-7.1-03 | Denial of Service | Stop-click flood with invalid runIds | accept | CancellationRegistry.cancel(UUID) is cheap (ConcurrentHashMap lookup + dispose no-op on absent id); load-bearing Phase 7 registry contract already idempotent |
| T-7.1-04 | Access Control bypass | Citation deep-link to /ai-agent/knowledge?documentId=X bypasses RAG allowedRoles filter | accept | KnowledgeBaseView enforces role gating on its own (Plan 07-06 @ViewPolicy + Jmix security); navigating via deep-link does NOT bypass RAG retrieval filter (tested in Phase 5 RAG tests) |
| T-7.1-05 | Race condition | Stop clicked right as Final event arrives → CANCELLED audit on a completed run | accept | RESEARCH Pitfall #3: CancellationRegistry.cancel guards with isDisposed() before emitting audit — Phase 5/7 registry contract; not worth re-verifying here |
</threat_model>
