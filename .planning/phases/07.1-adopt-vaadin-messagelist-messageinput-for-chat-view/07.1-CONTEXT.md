# Phase 7.1: Adopt Vaadin MessageList / MessageInput for Chat View - Context

**Gathered:** 2026-04-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Refactor the Phase 7 chat UI onto Vaadin's stock `com.vaadin.flow.component.messages.MessageList` + `MessageInput`, modeled on `jmix-ai-backend/view/chat/ChatView.java`. Net effect: remove the custom chat component tree, fold tool-call + citation rendering into a single `renderStreamEvent(StreamingEvent) → String` markdown formatter, keep all Phase 7 behavioral guarantees.

**In scope (from ROADMAP §Phase 7.1):**
- Replace `ChatPanelFragment` body with `MessageList` (markdown-enabled) + `MessageInput` composition
- Delete `MessageBubbleComponent`, `ToolCallCardComponent`, `MarkdownRenderer`
- Delete `CitationDialog` (folded into trailing markdown links — see D-01)
- Fold all event rendering into `renderStreamEvent(StreamingEvent) → String` following the reference
- Re-wire `ChatService.stream(...)` subscription to `doOnNext`/`doOnError`/`doOnComplete` with `ui.access(...)` + `MessageListItem.appendText(...)`
- Preserve Phase 7 guarantees: conversation-id query param, `New chat` with unsaved-confirm dialog, Stop action (D-03 integration), citation deep-link to KB, i18n coverage
- Update Phase 7 tests that referenced deleted classes; rewrite (not skip) where they cover still-required behavior
- Remove the `flexmark` dependency from `ai-agent.gradle` (markdown now handled by `MessageList.setMarkdown(true)`)

**Out of scope:**
- New chat features (search, editing, threading) — v2+
- Changing the streaming backend (`ChatService.stream`, `StreamingEvent` shape, `CancellationRegistry`) — Phase 5/6/7 contracts are frozen
- New UI views — Conversations/Parameters/KB/Audit views stay untouched
- Backporting MessageList pattern to `ConversationDetailView` — replay stays on its current implementation (separate follow-up if needed)

**Success criteria (from ROADMAP):**
1. `ChatView` + fragment ≤ ~250 lines combined (reference parity target)
2. No references to `MessageBubbleComponent` / `ToolCallCardComponent` / `MarkdownRenderer` remain in source or tests
3. Playwright UAT for Chat passes: streaming tokens render, tool-call events render as markdown blocks, citations surface as clickable links, `New chat` + conversation-id param work
4. `./gradlew test` green; Phase 7 tests updated (not skipped) where they referenced deleted types
5. i18n keys still resolve (consumes the `messages_en.properties` rename from pre-UAT fix)

</domain>

<decisions>
## Implementation Decisions

### Rendering

- **D-01 (Citations):** Trailing `**Sources:**` markdown list, ref-style. On `StreamingEvent.Citation`, accumulate citations; emit `"\n---\n**Sources:**"` once (on first citation of the turn) followed by `"\n- [docName](/ai-agent/knowledge?docId={uuid})"` per citation. Links resolve to the KnowledgeBase view filtered to that document (same deep-link target Phase 7 D-09 intended). **Delete `CitationDialog.java`** and its message keys — the snippet-preview modal is dropped. Rationale: `MessageList` renders static markdown; interactive per-token click handlers fight the component's model. Trailing list + deep-link keeps the KB navigation contract without custom DOM plumbing.

- **D-02 (Tool calls):** Fold into `renderStreamEvent` as markdown blocks (ref shape). Header on `ToolCall`: `"\n\n{ts} **{toolName}**: {argsSummary}"`. On `ToolResult`: `"  \n{ts} _{toolName} done in {Xms}_\n\n---\n"`. Any retrieved/reranked document lists (if our `StreamingEvent` variants carry them) render as inline `(score) url` lists matching the reference's `renderDocList`. No expand/collapse UX — loss of detail is acceptable; full tool args/results remain visible in `AiToolCallAudit`.

- **D-03 (Batching):** **Drop** the 50 ms `bufferTimeout(64)` coalescing. Per-event `ui.access(() -> botMsg.appendText(md))` matches the reference. Rationale: `MessageListItem.appendText` is designed for streaming; Vaadin Push batches server-side pushes at its own cadence; provider token rates in practice are well below DOM-thrash territory. If UAT surfaces perf issues with a fast provider, add back behind a config knob — capture as deferred (see Deferred Ideas).

### Control flow

- **D-04 (Stop):** Keep the Phase 7 D-03 `CancellationRegistry` integration. Stop click path: button → `CancellationRegistry.cancel(runId)` → `Flux.dispose()` via stored `Disposable` → `doOnError`/`doOnComplete` rewires input state. Audit row records `outcome=CANCELLED`. Stop surfaces as a separate `JmixButton` above or beside `MessageInput` (MessageInput has no built-in stop UI); visibility toggles mirror the current Fragment (`sendButton.setVisible(false) / stopButton.setVisible(true)` pattern collapses into an input-enabled/stop-visible toggle). **Do not** regress to the reference's bare `Disposable.dispose()` — the audit contract is load-bearing.

### Structure

- **D-05 (Fragment shell):** Keep `ChatPanelFragment` as a Jmix Fragment (`@FragmentDescriptor("chat-panel-fragment.xml")`). Its body is fully rewritten to hold `MessageList` + `MessageInput` + Stop button + stream disposable. `ChatView` continues to compose the Fragment. Rationale: preserves Phase 7 D-29's reusable substrate for the v2 floating-launcher / embedded surface without a second refactor later. Extra wrapper cost (~30-50 lines) is a deliberate payment against the ~250-line target.

- **D-06 (ChatView responsibilities):** `ChatView` owns: route (`@Route("ai-agent/chat")`), `@ViewController`/`@ViewDescriptor`, `conversationId` route param binding (`UrlQueryParametersFacet` + `AbstractUrlQueryParametersBinder`), `New chat` button + unsaved-confirm dialog wiring, Parameters profile picker, menu/role/i18n metadata. Streaming + MessageList lifecycle + Stop lives inside `ChatPanelFragment`. Same split as current Phase 7 shape — only the Fragment's internals change.

- **D-07 (conversationId carry-over):** Phase 7 D-26 route-param contract is preserved unchanged. Fragment exposes `setConversationId(UUID)` — on non-null, load transcript history into `MessageList.setItems(...)` as a list of `MessageListItem` (one per `AiMessage`, markdown body); on null, clear items and show empty state. Transcript-load logic migrates from `ChatPanelFragment.loadTranscript()` but now emits `MessageListItem` instead of `MessageBubbleComponent`. Role mapping: `USER → userColorIndex(0)` with "You" name; `ASSISTANT → userColorIndex(2)` with localized "AI Assistant" name.

### Tests

- **D-08 (Test fates):**
  - **Delete:** `MarkdownRendererXssTest` — `MarkdownRenderer` deleted; Vaadin's `MessageList.setMarkdown(true)` owns rendering + escaping.
  - **Delete:** any tests directly asserting `MessageBubbleComponent` / `ToolCallCardComponent` DOM shape.
  - **Rewrite (not skip):** `ChatViewStreamTest` — re-target at `MessageList` item text after stream completion (assert final markdown contains tool-call header + Sources list). `ChatViewStopTest` — re-target at Stop click → `CancellationRegistry.cancel` + audit `CANCELLED` row; MessageList item text shows whatever buffer was received before cancel.
  - **Add (if absent):** single test covering `renderStreamEvent(StreamingEvent) → String` purely as a pure-function unit test (no Vaadin context needed) — cheapest way to lock the markdown-format contract.

### i18n

- **D-09 (Markdown-fragment i18n):** The reference hardcodes English labels (`"Sources:"`, `"Retrieved"`, `"Reranked"`, `"done in"`) inside `renderStreamEvent`. We pull these through `MessageSource` via the existing `messages` / `messages_vi` bundles. Add keys under a new `chatView.stream.*` namespace: `chatView.stream.sources`, `chatView.stream.retrieved`, `chatView.stream.reranked`, `chatView.stream.doneIn`, `chatView.stream.conversationId`, `chatView.stream.model`, `chatView.stream.userPrompt`, `chatView.stream.receivedIn`, `chatView.message.userName`, `chatView.message.assistantName`. `renderStreamEvent` receives `MessageSource` (or a pre-resolved `Map<String, String>` keyed by label) from the Fragment so it remains testable as a pure function.

### Build / dependencies

- **D-10 (flexmark removal):** Remove `com.vladsch.flexmark:flexmark` from `ai-agent/ai-agent.gradle` along with the `MarkdownRenderer` class deletion. Re-run `./gradlew dependencies` to confirm no transitive consumers. Any callers of `MarkdownRenderer` outside the chat tree (none expected — verify with grep in planner phase) must be migrated or removed.

- **D-11 (Vaadin API verification):** Before planning locks structure, verify against current `com.vaadin.flow:flow-server` API (via Context7) that `MessageList.setMarkdown(true)`, `MessageListItem.appendText(String)`, `MessageListItem.setUserColorIndex(int)`, and the `MessageInput.SubmitEvent` shape match the reference's usage. The reference project is our own org's, so API surface should be identical — this is a sanity check, not a deep research task.

### Claude's Discretion

- Exact `renderStreamEvent` signature — pure static method vs instance method vs helper record — planner picks based on how i18n pulls through cleanly.
- Whether Stop button lives inside the `MessageInput` area (as a sibling button) or above the `MessageList` — visual placement only; functional contract is locked by D-04.
- `@Push` annotation placement (already decided in Phase 7 D-02 via AppShellConfigurator) — no change needed here.
- Exact `chatView.stream.*` key naming (may differ slightly; parity across en+vi is the hard requirement).
- Whether `scrollToBottom()` uses the reference's `setTimeout(..., 50)` JS trick or a simpler direct `scrollTop = scrollHeight` — whichever is reliable with markdown re-render.
- How New-chat unsaved-confirm detects "in-flight stream" — `activeStream != null && !activeStream.isDisposed()` is the natural signal. "Unsaved turns" is trivially true iff `messageList` has items; confirm dialog gates transition either way. Exact phrasing of the confirm text in both locales — follow existing key pattern.

</decisions>

### Reusable Assets (preserved through this refactor)
- `ChatService.stream(String userId, UUID conversationId, String text, ...)` (`com.vn.agent.ChatService`) — returns `Flux<StreamingEvent>`. Contract is frozen; only the subscriber changes.
- `StreamingEvent` sealed hierarchy (`com.vn.agent.orchestration.StreamingEvent`) — `Content`, `ToolCall`, `ToolResult`, `Citation`, `Error`, `Final`. `renderStreamEvent` exhaustively switches on these.
- `CancellationRegistry` (`com.vn.agent.rag`) — Stop wiring (D-04).
- `ConversationGateway.loadOrCreate(userId, conversationId, firstPrompt)` — ownership check during transcript load (D-07).

- `@ViewController` + `@ViewDescriptor` for ChatView; `@FragmentDescriptor` for ChatPanelFragment (Jmix XML + Java controller pair). Unchanged.
- `@ViewComponent` for XML-declared components; `@Autowired` for services. Unchanged.
- `UI.access(...)` for all off-thread DOM mutations (Push callbacks arrive on `ai-agent-stream` scheduler). Same rule applies with MessageList.
- `messages.properties` (en/base) + `messages_vi.properties` parity — every new `chatView.stream.*` key lands in both files.

### Integration Points
- `ai-agent/ai-agent.gradle` — flexmark dependency removal (D-10); `jmix-flowui-starter` already provides `com.vaadin.flow:flow-server` transitively, so no new dep for MessageList.
- `chat-panel-fragment.xml` — rewritten layout. Toolbar row (profile picker, Stop button, New-chat button) stays; body swaps `VerticalLayout` + `Scroller` + `TextArea` + Send button for `MessageList` + `MessageInput`.
- `messages.properties` / `messages_vi.properties` — new `chatView.stream.*` keys land here; ADD do not replace.

<specifics>
## Specific Ideas

- **Follow the reference structure closely** for `renderStreamEvent` — it is the ROADMAP-designated spec. Don't invent a novel event-to-markdown mapping; translate the existing Phase 7 render semantics into the reference's switch-expression shape.
- **Deep-link target for Sources list:** `/ai-agent/knowledge?docId={uuid}` (or whatever the KnowledgeBaseView's existing deep-link parameter is — planner to confirm from Phase 7 KB view code, don't invent a new route).
- **Preserve D-29:** even though reference has no Fragment, we keep it. The v2 floating-launcher use case is the reason we paid for the Fragment in Phase 7 — don't lose that investment in a refactor.
- **Do not regress audit coverage** — Stop's `CANCELLED` audit outcome is what makes the audit trail complete. Client-only dispose would break that.

</specifics>

<deferred>
## Deferred Ideas

- **Content-event bufferTimeout re-introduction:** If production/UAT surfaces DOM thrashing with a very fast provider, re-introduce `Flux.bufferTimeout(64, 50ms)` behind a config knob. Captured here so removing it is a deliberate choice, not a forgotten step.
- **Citation snippet preview:** Trailing `**Sources:**` list drops the CitationDialog's per-chunk snippet preview. If user research shows this was valuable, reintroduce as either: (a) markdown footnote with inline snippet, or (b) hover-tooltip on the source link. Neither requires reinstating a full modal component.
- **VirtualList for long transcripts:** Phase 7 D-06 deferred this. Still deferred — MessageList handles our conversation sizes fine.
- **MessageList adoption for ConversationDetailView (replay):** This phase refactors only `ChatView` / `ChatPanelFragment`. `ConversationDetailView` keeps its current bubble-based replay. Consider a follow-up once this phase stabilizes if UX consistency is worth the churn.
- **ChatProgressView retention:** Reference has a separate progress view; we don't. If planner finds our `ChatProgressView.java` is orphaned, delete it. If it's used by another code path, leave it. Not a gray area for this discussion — flag for planner triage.

</deferred>

  - **Effect on D-10:** flexmark dependency stays in `ai-agent.gradle` for this phase.
  - **Effect on Success Criterion #2:** Re-scoped to "no references to `MessageBubbleComponent` / `ToolCallCardComponent` / `MarkdownRenderer` / `CitationDialog` remain in `ChatView`, `ChatPanelFragment`, or their tests" (i.e., scoped to the chat-view subtree, not the whole repo). Full repo-wide deletion is deferred with D-12.
  - **Effect on D-08 (test fates):** `MarkdownRendererXssTest.java` is **kept** (class under test is still in use). `ChatViewStreamTest` + `ChatViewStopTest` rewrites stand.

- **D-12 (Deferred — full deletion + flexmark removal):** A follow-up phase must migrate `ConversationDetailView` to `MessageList`-based replay, after which `MarkdownRenderer`, `MessageBubbleComponent`, `MarkdownRendererXssTest`, and flexmark/owasp dependencies all drop. Added to Deferred Ideas.

- **A-02 (ChatProgressView triage):** Research confirms `ChatProgressView.java` does **not** exist in our codebase — it's a stale reference inherited from jmix-ai-backend. Remove from any task lists; no deletion needed.

- **A-03 (Deep-link param correction):** KnowledgeBaseView deep-link param is `documentId` (not `docId`). D-01 stands; just use the correct param name: `/ai-agent/knowledge?documentId={uuid}`. Extraction of a `ChatStreamController` helper is **deferred to a future phase** (tracked as D-12 follow-up) rather than forced under the original ceiling — the lambda chain + event fanout are cohesive enough that splitting now would be premature abstraction without a concrete second consumer (per `feedback_pragmatic_modules.md`). Any future regression that pushes past 375 must trigger the extraction.
