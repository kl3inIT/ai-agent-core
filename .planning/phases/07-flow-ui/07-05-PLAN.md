<objective>
Wave 2 plan. Ships UI-04: admin CRUD over AiParameters profiles with a hybrid Form+YAML layout. Form is source of truth (D-10); YAML is live read-only preview (D-12). Set active commits immediately (D-14). Admin-only per @ViewPolicy already landed in 07-01. Parallel-safe: only com.vn.agent.view.parameters/** touched; independent of 07-02 backend changes.

Purpose:
- Form covers ALL AiParametersBody fields per D-11 — no simplification to "common fields only". Every field in AiParametersBody gets a bound UI control.
- **List grid shows parsed fields, not raw YAML.** A column displaying the whole `yamlBody` blob is user-hostile (newlines, multi-line keys, hundreds of chars per row). The grid parses each row's YAML via AiParametersBodyYamlMapper once and surfaces Name, Model, Active (badge), createdDate — the raw YAML is visible only in the detail view's YAML tab.
- YAML preview uses existing AiParametersBodyYamlMapper (Phase 6-02). Regenerate live on valueChange (D-12).
- **enabledTools list comes from the live @Tool registry.** No hardcoded six-name fallback. If the registry returns zero tools at view init, the view fails fast with a user-visible error (misconfigured deploy is a bug, not a UI concern to paper over).
- Validation is per-field inline (D-13); Save disabled while any field is invalid. Reuses Phase 6 Jakarta validation keys (ai-agent.parameters.*.range/required) AND new UI-SPEC keys (parametersDetail.validation.*).
</objective>
