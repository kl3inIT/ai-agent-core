# Phase 10 — UI Design Contract
## AI-Specific LLM Exposure Policy

> Visual and interaction contract for Jmix Flow UI views.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
> This is a server-side Vaadin Flow application rendered through Jmix XML view descriptors + Java
> controllers. NOT a SPA. shadcn gate: not applicable.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Jmix Flow UI + Vaadin Design System (Lumo theme) |
| Preset | not applicable |
| Component library | Jmix Flow UI components (jmix-flowui); Vaadin Lumo theme |
| Icon library | vaadin:* icon set (existing convention — see `vaadin:close-small`, `vaadin:question-circle-o` in reference UI) |
| Font | Vaadin Lumo default (Inter / system-sans-serif stack) — no custom font declared in project |

> Source: Existing view XML files (`audit`, `knowledge`, `parameters` views), jmix-ai-backend
> reference, and project CLAUDE.md conventions. No Tailwind, no shadcn, no custom CSS tokens.

---

## Spacing Scale

Jmix/Vaadin Lumo spacing tokens — mapped to the 8-point grid:

| Token | Lumo CSS var | px equiv | Usage |
|-------|-------------|----------|-------|
| xs | `--lumo-space-xs` | 4px | Icon gaps, inline label padding |
| sm | `--lumo-space-s` | 8px | Compact hbox spacing (`spacing="true"`) |
| md | `--lumo-space-m` | 16px | Default layout padding (`padding="true"`) |
| lg | `--lumo-space-l` | 24px | Section separation |
| xl | `--lumo-space-xl` | 32px | Major panel gaps |

> All XML layout attributes use Jmix semantic names (`spacing`, `padding`) which resolve to Lumo
> variables. No custom pixel values. Matches existing views verbatim.

Exceptions:
- Metadata filter input row: `width="100%"` hbox with `minWidth="8em"` label span (mirrors
  jmix-ai-backend `vector-store-view.xml` line 25 exactly).
- Content cell expand area: `minRows="5" maxRows="20"` (mirrors jmix-ai-backend
  `vector-store-detail-view.xml` line 22).

---

## Typography

Vaadin Lumo typography — no custom sizes declared in project. Executor must NOT introduce inline
style overrides.

| Role | Lumo Token | px equiv | Weight | Line Height |
|------|-----------|----------|--------|-------------|
| Body / cell text | `--lumo-font-size-m` | 14px | 400 | 1.5 |
| Label / column header | `--lumo-font-size-s` | 12px | 600 | 1.4 |
| View title | `--lumo-font-size-xl` | 20px | 600 | 1.2 |
| Compact badge / status | `--lumo-font-size-xs` | 11px | 400 | 1.3 |

> Source: Lumo defaults applied by all existing views. Matches `parametersList`, `auditList`, and
> `knowledgeBase` views without deviation.

---

## Color

Vaadin Lumo semantic colors — all existing views use these exclusively.

| Role | Lumo Token | Usage |
|------|-----------|-------|
| Dominant (60%) | `--lumo-base-color` | Page background, grid rows |
| Secondary (30%) | `--lumo-contrast-5pct` | Card, panel, filter bar backgrounds |
| Accent (10%) | `--lumo-primary-color` | Specific elements listed below only |
| Destructive | `--lumo-error-color` | Delete button `themeNames="error"` only |
| Success / positive | `--lumo-success-color` | "Visible to AI" toggle button (`themeNames="success"`) |

Accent (`--lumo-primary-color`) reserved for:
- "Hide from AI" toggle button when rule is enabled (`themeNames="primary"`)
- Upload submit / metadata filter "Update" button (`themeNames="primary"` on comboButton)
- `setActive` action button (`themeNames="primary success"`) — existing pattern from parameters view

> Rule: accent is NEVER applied to column headers, form labels, or passive status text.
> Do NOT use `themeNames="warning"` anywhere in Phase 10 views (jmix-ai-backend uses it for
> "Remove All" — that action does not exist in v1.1 debug view).

## Surface-by-Surface Contract

### Surface 1: AiExposureRuleListView

**View id:** `AiAgent_AiExposureRule.list`
**Route:** admin menu entry `aiAgent.exposureRules.list`
**Layout structure:** `layout padding="true" spacing="true"` (matches auditList pattern)
**Focal point:** `createBtn` (Create Rule, primary accent via `list_create` built-in action)

#### Filter bar
- `<genericFilter id="exposureRulesFilter" dataLoader="exposureRulesDl">`
- Inside filter: `<propertyFilter property="entityName" .../>` and
  `<propertyFilter property="enabled" .../>` declared as default conditions.
- No hand-built hbox filter bar. Source: CONTEXT.md D-10 + MEMORY `feedback_jmix_generic_filter`.

#### Buttons panel
```
<hbox id="buttonsPanel" classNames="buttons-panel">
    <button id="createBtn" action="exposureRulesDataGrid.createAction"/>
    <button id="editBtn"   action="exposureRulesDataGrid.editAction"/>
    <button id="removeBtn" action="exposureRulesDataGrid.removeAction"/>
</hbox>
```
Built-in list actions declared via `list_create`, `list_edit`, `list_remove` action types inside
`<actions>` on the dataGrid. Source: MEMORY `feedback_jmix_list_item_tracking`.

#### DataGrid columns
| column key / property | Header key | Renderer |
|----------------------|-----------|---------|
| `property="entityName"` | `exposureRulesList.column.entityName` | plain text |
| `property="enabled"` | `exposureRulesList.column.enabled` | `@Supply` badge renderer |
| `property="createdDate"` | (entity default) | plain text |
| `key="toggleAction"` | `exposureRulesList.column.actions` | `@Supply` toggle button renderer |

- `resizable="true"` on `<columns>`.
- `themeNames="compact"` on `<dataGrid>` (matches audit and knowledge views).

#### Action column toggle button — visual contract
- **Enabled rule (denylisted):** button label = `msg://exposureRulesList.action.hideFromAi`,
  icon = `vaadin:eye-slash`, `themeNames="primary"` (accent color, communicates "currently
  active/hiding"). Tooltip = `msg://exposureRulesList.action.hideFromAi.tooltip`.
- **Disabled rule (not denylisting):** button label = `msg://exposureRulesList.action.visibleToAi`,
  icon = `vaadin:eye`, `themeNames="success"` (success color, communicates "currently visible").
  Tooltip = `msg://exposureRulesList.action.visibleToAi.tooltip`.
- Single click flips the bit via `UnconstrainedDataManager`, refreshes the row, publishes
  `LlmExposureChangedEvent`. No dialog confirmation (toggle is reversible).
- Source: CONTEXT.md D-10, MEMORY `feedback_jmix_action_column_renderer`.
- Executor pattern: `@Supply(to = "exposureRulesDataGrid.toggleAction", subject = "renderer")`
  returning a `ComponentRenderer` that calls `DataGridRenderers.buildActionsColumn` or a direct
  `Button` with label/icon set from the row's `enabled` field.

#### Empty state
- Heading: `msg://exposureRulesList.empty.heading`
  EN: "No exposure rules"
  VI: "Chưa có quy tắc kiểm soát"
- Body: `msg://exposureRulesList.empty.body`
  EN: "Add a rule to hide an entity from the AI. The AI will treat it as if it does not exist."
  VI: "Thêm quy tắc để ẩn thực thể khỏi AI. AI sẽ coi thực thể đó như không tồn tại."

### Surface 2: AiExposureRuleDetailView

**View id:** `AiAgent_AiExposureRule.detail`
**Layout:** `<formLayout>` with single-column `<responsiveStep minWidth="0" columns="1"/>`.
**Focal point:** `saveBtn` (Save Rule, primary accent)

#### Fields
| Field | Component | Notes |

| `entityName` | `<comboBox>` | Populated via controller from `Metadata.getSession().getClasses()`, filtered to exclude `@SystemLevel` + AI-* internals. Label = `msg://exposureRulesDetail.field.entityName`. `required="true"`. |

  standard `formLayout`; omit from new-record form.

#### Metaclass dropdown — display contract
- Item label format: `"{localizedLabel} ({metaClassName})"` — human-readable name first, internal
  name in parentheses for disambiguation.
- Items sorted alphabetically by localized label.
- Empty / no-selection placeholder: `msg://exposureRulesDetail.field.entityName.placeholder`
  EN: "Select entity..."
  VI: "Chọn thực thể..."
- Helper text below comboBox: `msg://exposureRulesDetail.field.entityName.helper`
  EN: "Choose the Jmix entity to hide from AI tools and the knowledge base."
  VI: "Chọn thực thể Jmix cần ẩn khỏi công cụ AI và cơ sở tri thức."

#### Actions bar
```

```

### Surface 3: KnowledgeBaseView — Extensions

**View id:** `AiAgent_KnowledgeBase` (existing view extended, NOT replaced)
**Focal point:** `uploadSubmitBtn` (primary accent — triggers upload + ingest with collected metadata)

#### Upload form additions (above existing `<upload>`)
New `<formLayout id="uploadMetaForm">` inserted between the `<upload>` component and the
`<dataGrid>`. Visible only when `upload` component has files pending (or always visible — executor
chooses based on UX simplicity; always-visible is simpler). Contains:

| Field | Component | Notes |
|-------|-----------|-------|
| `allowedRoles` | existing roles multi-select (already in upload handler) | Promoted to visible form field with label `msg://knowledgeBase.upload.field.allowedRoles` |
| `sourceEntityName` | `<comboBox>` | Same metaclass dropdown helper as detail view. Optional (nullable). Label = `msg://knowledgeBase.upload.field.sourceEntityName`. |

- Both fields collected BEFORE the upload/ingest starts. Source: CONTEXT.md D-07.
- Helper text for `sourceEntityName`: `msg://knowledgeBase.upload.field.sourceEntityName.helper`
  EN: "Optional. Link this document to an entity so the AI skips it when that entity is denied."
  VI: "Tuỳ chọn. Liên kết tài liệu với thực thể để AI bỏ qua nếu thực thể đó bị ẩn."

#### Row actions additions
New actions inside the existing `<dataGrid id="documentsDataGrid">` `<actions>` block:

| Action id | Type | Label key |
|-----------|------|-----------|
| `editPermissions` | `list_itemTracking` | `msg://knowledgeBase.action.editPermissions` |
| `reingest` | `list_itemTracking` (already exists) | `msg://knowledgeBase.action.reingest` (already exists) |

- "Edit permissions" opens a dialog (or detail fragment) collecting `allowedRoles` +
  `sourceEntityName`. On save: `DataManager.save()` the document row, then schedule reingest via
  `AsyncIngestionWorker.enqueue(...)`. Source: CONTEXT.md D-08.
- "Reingest" triggers reingest on the selected row regardless of changes. Source: CONTEXT.md D-08.
- Both buttons in `<hbox id="rowActionsBar">` alongside the existing "Delete" button.
  "Delete" retains `themeNames="error"`. No theme override on new buttons (default neutral).

#### Additional column
New column in the grid: `key="sourceEntity"` with header `msg://knowledgeBase.column.sourceEntity`.
Rendered via `@Supply` renderer — shows the entity localized label when set, or a dash (`—`) when
null. Position: after the existing `roles` column.

### Surface 4: VectorStoreDebugView

**View id:** `AiAgent_VectorStoreDebug`
**Route:** admin menu entry `aiAgent.vectorStoreDebug`
**Access:** `AiAgentAdminRole` only (admin bypass in `RetrievalFilterBuilder` applies — admin sees
all chunks without entity denylist filter)
**Focal point:** `searchBtn` (Search, primary accent)

**Layout structure:** `layout padding="true" spacing="true"` (matches audit view)

#### Filter input row
```xml
<hbox alignItems="CENTER" width="100%">
    <span text="msg://vectorStoreDebug.filter.label" minWidth="8em"/>
    <textField id="metadataFilterField" width="100%" datatype="string">
        <suffix>
            <hbox spacing="false">
                <button id="filterClearBtn"  themeNames="tertiary-inline" icon="vaadin:close-small"
                        title="msg://vectorStoreDebug.filter.clear"/>
                <button id="filterHelpBtn"   themeNames="tertiary-inline" icon="vaadin:question-circle-o"
                        title="msg://vectorStoreDebug.filter.help"/>
            </hbox>
        </suffix>
    </textField>
</hbox>
```
- Mirrors jmix-ai-backend `vector-store-view.xml` lines 24-36 exactly.
- Filter input uses `FilterExpressionTextParser` (confirmed present in Spring AI 1.1.4 — see
  `NinExpressionContext.class` in jar). Controller parses the text to `Filter.Expression` and
  passes to `VectorStore.similaritySearch(SearchRequest.builder().withFilterExpression(expr)...)`.
- Help tooltip content (shown in Vaadin `title`): simple expression syntax examples, e.g.
  `source_entity == 'Order' AND role_ai-agent-user == true`. Full help text stored in message key
  `vectorStoreDebug.filter.help.tooltip`.
- Parse error shown as inline notification below the field (Vaadin `errorMessage` on the
  textField), not a toast.
- **Accessibility:** `filterClearBtn` and `filterHelpBtn` are icon-only. In addition to the XML
  `title` attribute, the executor MUST call `filterClearBtn.setAriaLabel(messages.getMessage(...,
  "vectorStoreDebug.filter.clear"))` and `filterHelpBtn.setAriaLabel(messages.getMessage(...,
  "vectorStoreDebug.filter.help"))` in the controller's `onInit` (or equivalent `@Subscribe
  InitEvent` handler) so screen readers expose the same label as the tooltip. Message keys
  `vectorStoreDebug.filter.clear` and `vectorStoreDebug.filter.help` already exist in the
  inventory below.

#### Buttons row
```xml
<hbox id="buttonsPanel" classNames="buttons-panel">
    <button id="searchBtn"   text="msg://vectorStoreDebug.action.search" themeNames="primary"/>
    <button id="refreshBtn"  action="chunksDataGrid.refreshAction"/>
    <simplePagination id="pagination" dataLoader="chunksDl"/>
</hbox>
```
- NO remove / edit / update actions. Read-only in v1.1. Source: CONTEXT.md D-09, `<deferred>`.
- `simplePagination` with `pageSize="20"` default (default; planner may adjust; 20 rows per page
  is standard for dense admin grids).

#### DataGrid columns
| column key | Header key | Renderer / notes |
|-----------|-----------|------------------|
| `property="id"` | `vectorStoreDebug.column.id` | plain text; `width="260px"` fixed (UUID length) |
| `key="content"` | `vectorStoreDebug.column.content` | `@Supply` renderer — truncated to 120 chars with "Show full" button that opens detail dialog |
| `key="metadata"` | `vectorStoreDebug.column.metadata` | `@Supply` renderer — compact single-line JSON preview truncated to 80 chars, click opens detail dialog |

- Grid: `themeNames="compact"`, `resizable="true"`, `sortable="false"` (data provider is not
  sortable — similarity search order is fixed). Source: jmix-ai-backend `vector-store-view.xml`.
- `columnReorderingAllowed="true"`.

#### Content cell expand — "Show full" UX
- Clicking "Show full" button (inline `<button themeNames="tertiary-inline" icon="vaadin:expand">`)
  opens `DialogWindow` (Jmix `DialogWindows`) containing a `<textArea>` with the full content and
  metadata side-by-side. Mirrors jmix-ai-backend `vector-store-detail-view.xml` `formLayout`
  with `textArea minRows="5" maxRows="20"` for content and `textArea minRows="5" maxRows="10"` for
  metadata. Expand button text: `msg://vectorStoreDebug.action.expand`
  EN: "Show full" / VI: "Xem đầy đủ".
- Dialog title: `msg://vectorStoreDebug.detail.title` EN: "Chunk detail" / VI: "Chi tiết đoạn".
- Dialog close button: `msg://vectorStoreDebug.detail.close` EN: "Close" / VI: "Đóng".

#### Empty state
- Grid shows empty state when no chunks returned.
- Heading: `msg://vectorStoreDebug.empty.heading`
  EN: "No chunks found"
  VI: "Không tìm thấy đoạn nào"
- Body: `msg://vectorStoreDebug.empty.body`
  EN: "Adjust the filter expression or upload documents in the Knowledge base."
  VI: "Điều chỉnh biểu thức lọc hoặc tải tài liệu lên Cơ sở tri thức."

```java
@Supply(to = "exposureRulesDataGrid.toggleAction", subject = "renderer")
private ComponentRenderer<Button, AiExposureRule> toggleRenderer() {
    return new ComponentRenderer<>(rule -> {
        Button btn = new Button();
        if (rule.getEnabled()) {
            btn.setText(messages.getMessage(getClass(), "exposureRulesList.action.hideFromAi"));
            btn.setIcon(VaadinIcon.EYE_SLASH.create());

            btn.setIcon(VaadinIcon.EYE.create());

    });
}
```
