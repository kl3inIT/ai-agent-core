### `entity/AiAuditEvent.java` (NEW — entity, self-ref `@Composition`)

**Primary analog:** `com/vn/agent/entity/AiConversation.java` (proven `@Composition`)
**Secondary analog (column carry-over):** `com/vn/agent/entity/AiToolCallAudit.java`

**Class header pattern** (from `AiConversation.java:16-22`):
```java
@Store(name = "agentstore")
@JmixEntity
@Entity(name = "ai_AiConversation")
@Table(name = "AI_AGENT_CONVERSATION", indexes = {
        @Index(name = "IDX_AI_AGENT_CONVERSATION__ON_CREATED_BY", columnList = "CREATED_BY")

public class AiConversation {
```
→ For `AiAuditEvent`: use `@Entity(name = "ai_AiAuditEvent")`, `@Table(name = "AI_AGENT_AUDIT_EVENT", ...)`, indexes on `PARENT_ID`, `CONVERSATION_ID`, `STARTED_AT`, `RUN_ID` (mirror `AiToolCallAudit.java:16-19` index set + new `PARENT_ID` index).

**UUID + Version pattern** (from `AiConversation.java:24-31` / `AiToolCallAudit.java:22-29`):
```java
@Id @Column(name = "ID", nullable = false) @JmixGeneratedValue
private UUID id;

@Version @Column(name = "VERSION", nullable = false)

```

**`@Composition` parent→children** (from `AiConversation.java:50-53`):
```java
@Composition
@OnDelete(DeletePolicy.CASCADE)
@OneToMany(mappedBy = "conversation", cascade = CascadeType.ALL, orphanRemoval = true)
private List<AiMessage> messages;
```
→ For self-ref, `mappedBy = "parent"` and `List<AiAuditEvent> children`. Keep `@Composition` + `cascade = CascadeType.ALL` + `orphanRemoval = true` BUT beware of Pitfall #1 on UPDATE (see `AuditWriter.writeChatFinish` pattern below — fetch-plan must omit `children`).

**Child side `@ManyToOne`** (from `AiMessage.java:32-36`):
```java
@NotNull
@ManyToOne(fetch = FetchType.LAZY, optional = false)
@OnDelete(DeletePolicy.CASCADE)
@JoinColumn(name = "CONVERSATION_ID", nullable = false)

```
→ For `AiAuditEvent`: `optional = true`, `nullable = true` (root has no parent). Drop `@NotNull` and `nullable = false`. `@JoinColumn(name = "PARENT_ID")`.

**`@InstanceName` with derived display** (from `AiMessage.java:51-55` + `AiToolCallAudit.java:82-86`):
```java
@InstanceName
@DependsOnProperties({"role", "createdDate"})
public String getDisplayName() {
    return String.format("%s @ %s", role, createdDate);
}
```
→ For `AiAuditEvent`: `@DependsOnProperties({"kind", "eventName", "outcome"})`, return `kind + " / " + (eventName == null ? "-" : eventName) + " / " + (outcome == null ? "..." : outcome)` (CONTEXT.md §Claude's Discretion — planner picks final null-placeholder).

**String-column + enum getter/setter idiom** (from `AiToolCallAudit.java:50-52, 88-89`):
```java
@NotNull @Column(name = "OUTCOME", nullable = false, length = 16)
private String outcome;
// ...
public AiToolCallOutcome getOutcome() { return outcome == null ? null : AiToolCallOutcome.fromId(outcome); }
public void setOutcome(AiToolCallOutcome outcome) { this.outcome = outcome == null ? null : outcome.getId(); }
```
→ For `AiAuditEvent`: `outcome` must become `nullable = true` (CHAT row is null until finish). KEEP the String + enum-id indirection pattern (RESEARCH §Open Question 5 — no change).

**Columns to carry forward** (from `AiToolCallAudit.java:31-80`):
- Keep: `conversation` (ManyToOne), `userUsername`, `argumentsJson` (`@Lob`), `resultSummary` (`@Lob`), `outcome`, `denialReason`, `latencyMs`, `startedAt`, `finishedAt`, `runId`, `promptHash`, `errorClass`, `kind`
- Rename: `TOOL_NAME` (nullable `length=128`) → `EVENT_NAME` (same, also nullable — CHAT root has no event name)
- Drop: `phase` (PRE/POST discriminator gone)
- Widen: `KIND` from `length=8` → `length=16` (future kinds per D-03)
- Add: `parent` (ManyToOne, self-ref), `children` (OneToMany), retrieval-only columns: `queryText` (@Lob), `topK` (Integer), `hitCount` (Integer), `topScore` (Double), `filtersJson` (@Lob)

**UPDATE path (NEW — `writeChatFinish`)** — pattern synthesized from `@Transactional` header + fetch-plan load:
```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public void writeChatFinish(UUID rootId, long latencyMs, String outcome, String errorClass) {
    AiAuditEvent root = dataManager.load(AiAuditEvent.class)
            .id(rootId)
            .fetchPlan(fp -> fp.addProperty("kind")
                    .addProperty("outcome")
                    .addProperty("latencyMs")
                    .addProperty("finishedAt")
                    .addProperty("errorClass")
                    .addProperty("startedAt"))  // NEVER include "children" — Pitfall #1
            .optional()
            .orElse(null);
    if (root == null) {
        log.warn("writeChatFinish: root {} not found; lost", rootId);
        return;
    }
    root.setFinishedAt(OffsetDateTime.now());
    root.setLatencyMs(latencyMs);
    root.setOutcome(outcome);
    root.setErrorClass(errorClass);
    dataManager.save(root);

    registerAfterCommit(rootId, AuditKind.CHAT);   // D-05: fan-out on finish (root becomes durable+complete)
}
```
Rationale in RESEARCH §Pitfall #1: populating `children` triggers cascade re-save / orphan-removal.

Call from `writeChatFinish` (kind=CHAT), `writeToolCall` (kind=TOOL), `writeRetrieval` (kind=RETRIEVAL). D-05: NOT from `writeChatStart`.

**`writeToolCall` signature change** (from existing lines 122-126):

→ Drop `phase` parameter. Add `UUID parentId`. Collapse PRE/POST into one INSERT: set both `startedAt` and `finishedAt` at insert time (children are append-only per D-01). Set `eventName = toolName`, `kind = AuditKind.TOOL`.

**`writeRetrieval` NEW method** — same shape as `writeToolCall` INSERT:
```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public UUID writeRetrieval(UUID parentId, UUID runId, String userUsername, UUID conversationId,
                           String queryText, Integer topK, Integer hitCount, Double topScore,
                           String filtersJson, long latencyMs, String outcome, String errorClass) {
    AiAuditEvent row = metadata.create(AiAuditEvent.class);
    row.setRunId(runId);
    row.setKind(AuditKind.RETRIEVAL);
    // resolve parent by id (lazy load, no children fetch)
    if (parentId != null) {
        AiAuditEvent parent = dataManager.load(AiAuditEvent.class).id(parentId).optional().orElse(null);
        if (parent != null) row.setParent(parent);
    }
    // ... set queryText/topK/hitCount/topScore/filtersJson/latencyMs/outcome/errorClass
    OffsetDateTime now = OffsetDateTime.now();
    row.setStartedAt(now.minusNanos(latencyMs * 1_000_000L));
    row.setFinishedAt(now);
    dataManager.save(row);
    final UUID auditId = row.getId();
    registerAfterCommit(auditId, AuditKind.RETRIEVAL);
    return auditId;
}
```
Sentinel drop: CONTEXT.md removes `CHAT_TOOL_NAME_SENTINEL = "<chat>"` — `eventName` is nullable for CHAT roots.

### Shared Pattern 1: `REQUIRES_NEW` Tx Method + `afterCommit` Fan-Out

**Source:** `audit/AuditWriter.java:58-80, 122-168`
**Apply to:** Every new public method on `AuditWriter` (`writeChatStart`, `writeChatFinish`, `writeToolCall`, `writeRetrieval`)

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public UUID writeXxx(...) {
    AiAuditEvent row = metadata.create(AiAuditEvent.class);
    // ... set scalar fields + resolve FK parents via dataManager.load(...).optional().orElse(null)
    dataManager.save(row);
    final UUID auditId = row.getId();
    registerAfterCommit(auditId, AuditKind.XXX);
    return auditId;
}

private void registerAfterCommit(UUID auditId, String kind) {
    if (TransactionSynchronizationManager.isSynchronizationActive()) {
        TransactionSynchronizationManager.registerSynchronization(new TransactionSynchronization() {
            @Override public void afterCommit() {
                dispatcher.dispatchEventAudited(auditId, kind);
            }
        });
    } else {
        log.warn("No active synchronization for auditId={} kind={}; firing inline", auditId, kind);
        dispatcher.dispatchEventAudited(auditId, kind);
    }
}
```
**Invariant — Pitfall #3:** NEVER call `AuditWriter.writeXxx` from inside another `AuditWriter.writeYyy`; always go through the injected proxy. `writeChatStart` is the single exception with NO `registerAfterCommit` call (D-05).
