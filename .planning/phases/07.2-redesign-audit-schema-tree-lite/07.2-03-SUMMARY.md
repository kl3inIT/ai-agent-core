## Deviations from Plan

### Rule 3 — Blocker: per-request topK source

**[Rule 3 - Blocker] DefaultChatServiceImpl has no local `topK` variable**
- Issue: Plan Task 3 action text read "RunContext.setRetrievalTopK(topK) ... if topK is a primitive int in the current code". There is no local `topK` variable in `ask()` or `stream()` — the factory bakes `props.resolvedTopK()` into the retriever builder; no per-request override exists.
- Fix: Injected `AiAgentRagProperties` via constructor; call `ragProperties.resolvedTopK()` at the same site. This records the value the retriever will actually use.
- Files: `DefaultChatServiceImpl.java` (constructor signature + field + two setter sites)
- Risk: adds a constructor arg. Test callers `AskTypedRetryTest` and `ChatServiceFilterParamContractTest` still use the old constructor — out of scope for Wave 3 (Wave 5 test work will fix them per plan guidance).

### Rule 2 — Stream() symmetry

**[Rule 2 - Critical] stream() also needs RunContext retrieval params**
- Issue: Plan spec only called out `ask()`; `stream()` is a parallel entry point that also invokes the advisor chain. Leaving it un-populated would mean RETRIEVAL audit rows from streamed turns carry `null` topK/filtersJson.
- Fix: Same two-line setter block inserted in `stream()` right after `ragFilter` is computed (Flux.defer body).
- Risk: none — same state semantics as ask().
