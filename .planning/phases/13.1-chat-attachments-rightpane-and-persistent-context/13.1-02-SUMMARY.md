# Phase 13.1 Plan 02: Per-Turn-All Resolver + Budget Cap + Audit Summary

Wave-1 resolver rewrite for Phase 13.1 — replaces Phase 13's single-turn `resolvePending(injectedAt IS NULL)` with `resolveActive(UUID)` that loads ALL non-expired `AiTaskFile` rows for the conversation in `createdDate DESC`, applies `perTurnMaxFiles`+`perTurnMaxTotalBytes` caps with LRU eviction, and emits one `task_file_budget_exceeded` audit row through `AuditWriter.writeToolCall` on overflow. The `Resolved` record's `taskFileIds` field is replaced by a `budgetExceeded` boolean. `AiTaskFileRepository.markInjected` and `loadPending` are deleted; the repository is now a TTL-cleanup-only seam.

## Final `resolveActive` Signature

```java
public Resolved resolveActive(UUID conversationId) {
    if (conversationId == null) return Resolved.empty();
    List<AiTaskFile> rows = dataManager.load(AiTaskFile.class)
        .query("select e from ai_AiTaskFile e " +
               "where e.conversation.id = :cid and e.expiresAt > :now " +
               "order by e.createdDate desc")
        .parameter("cid", conversationId)
        .parameter("now", OffsetDateTime.now())
        .list();
    // ... cap loop (kept newest-first; oldest dropped first per LRU) ...
    // ... if (budgetExceeded) auditWriter.writeToolCall(..., "task_file_budget_exceeded", ...) ...
    return new Resolved(media, budgetExceeded);
}
```

Key invariants:

- **JPQL DESC, not LIMIT**: byte-cap requires per-row summation; expressed in JVM, not SQL.
- **Sentinel handling**: `maxFiles == -1` disables file cap; `maxBytes == -1` disables byte cap; both `-1` returns every row with zero audit rows.
- **MIME map / `buildMedia` / `readFileBytes` / `sanitizeMediaName` / `resolveSupportedMimeType` / `tryParseMimeType` / `mimeTypeFromExtension` / `MAX_MEDIA_NAME_LENGTH` / `SUPPORTED_MEDIA_TYPES` / `EXTENSION_MIME_TYPES` are preserved verbatim** from Phase 13 (TEST-16 invariant + research §Common Operation 2).

## New `Resolved` Record Shape

```java
public record Resolved(List<Media> media, boolean budgetExceeded) {
    public static Resolved empty() { return new Resolved(List.of(), false); }
    public boolean isEmpty() { return media.isEmpty(); }
}
```

`taskFileIds` is removed — the per-turn-all model has no pending-state marker, so no row-id list needs to thread back to a `markInjected` stamp.

## Methods Deleted from `AiTaskFileRepository`

- `public List<AiTaskFile> loadPending(UUID conversationId)` — gone (resolver now loads via `DataManager` directly).
- `public void markInjected(List<UUID> taskFileIds, UUID userMessageId, OffsetDateTime injectedAt)` — gone (per-turn-all has no pending marker; `injectedAt` column dropped in Plan 13.1-01).

Repository now exposes ONLY `loadExpired(OffsetDateTime)`, `deleteRow(AiTaskFile)`, `deleteAllExpired(OffsetDateTime)`. The class JavaDoc "Owns the per-conversation pending lookup, the post-send markInjected stamping, and the TTL cleanup orchestration..." is rewritten to "Owns the TTL cleanup orchestration consumed by AiTaskFileCleanupJob (Phase 13.1: per-turn-all resolver loads rows directly via DataManager — no repo intermediary)."

The unused `AiMessage` and `Optional` imports are gone with the methods. The constructor's `DataManager` parameter is retained (`requireNonNull`-asserted) so existing Spring autowiring at the consumer side is unchanged across this wave.
