## Side-finding (in-session fix, not a Phase 13.1 gap)

While inspecting the audit log during Test 9, the user flagged that the conversations grid shows many rows with blank titles AND the audit log frequently records `denialReason="rejected_title:blank title"`. Root-caused to two compounding issues outside Phase 13.1's scope:

1. **Upload-first conversations:** `ChatPanelFragment.ensureConversationIdForUpload` calls `ConversationGateway.loadOrCreate(user, null, null)` (no firstMessage). The gateway sets `title=null` for the row. When the title-eligibility event fires later, `AiConversationTitleService.onConversationTitleEligible` checks `sameTitle(conversation.getTitle(), defaultTitle)` — which is false for a null title — and exits early. The conversation never gets auto-titled.
2. **LLM blank/sentinel/forbidden replies:** `sanitizeTitle` throws `IllegalArgumentException`, the catch block writes a `denialReason="rejected_title:blank title"` (or similar) audit row, and the conversation title is left untouched. Combined with #1, upload-first conversations stay blank forever.

**Fix applied** in `ai-agent/.../conversation/AiConversationTitleService.java`:
- Treat null/blank existing title as eligible (alongside the existing "matches default" path); only skip when the user has manually edited.
- Seed the conversation with `defaultTitle` (truncated first user message) BEFORE the LLM call when the existing title is null/blank, so a rejected/blank model reply still leaves a usable title on the row.
- Post-LLM reload check accepts null/blank/default-matched current title as overwriteable; only manual edits block.

**Tests:** `AiConversationTitleServiceTest` — 2 stale tests updated to match the actual current audit shape (Phase 13.1 UAT-fix-02 already changed it to outcome=SUCCESS + `rejected_title:<reason>` denialReason; the tests were never refreshed). 2 new tests added: `uploadFirstConversationWithNullTitleIsSeededAndUpgradedByModel` and `uploadFirstConversationKeepsSeededTitleWhenModelReturnsBlank`. All 12 tests pass.

**Hot-reload required** for the running app at port 8088 to pick up the new class.
