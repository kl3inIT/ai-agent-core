Close UAT Gap 2 (test 12, major — MODEL-02 catch+reissue feature is effectively dead code on the live OpenRouter/WebClient stack). Two compounding root causes per the UAT diagnosis:

1. **Wrong exception type recognized.** Spring AI's reactive/OpenRouter path throws `org.springframework.web.reactive.function.client.WebClientResponseException$BadRequest` (a sibling of `RestClientResponseException`, NOT a subclass — different package). Plan 16-07's classifier only walks for `RestClientResponseException` and `NonTransientAiException` wrapping one → never matches → blocking-path catch is dead code on this stack.

2. **Streaming path is not wrapped.** Plan 16-07 only wrapped `executeBlockingTurn(...)`. The user-facing chat surface uses `stream(...)` (reactive Flux). Streaming bad-model errors fall through to the existing `.onErrorResume(ex -> Flux.just(mapToStreamingError(ex)))` at line 719 → render generic error → no toast, no audit row, no `ChatModelFallbackAppliedEvent`.

Fix: (a) extend the classifier triad (`isBadModelException` + `matchesBadModelShape` + `findCausalRcre`) to recognize `WebClientResponseException` alongside `RestClientResponseException`; (b) wrap the `content` Flux inside `Flux.defer` at the streaming call site with a `.onErrorResume(...)` that runs the same bad-model classifier and, on match, delegates to `executeBlockingTurn(...)` (reuses the existing catch+reissue + audit + publish machinery — no duplication via the extracted `applyFallbackAuditAndPublish` helper).

Purpose: User-facing chat under a misconfigured `AiParameters.bodyYaml.model` (e.g. `openai/gpt-4o-uat-custom` from UAT test 12) now produces the yellow "Used default model for this turn." toast, writes a `MODEL_VALIDATION_FAILURE` audit row correlated by runId, and recovers the turn — instead of surfacing the generic "Đã xảy ra lỗi" error and leaving the operator with no forensic trail.

Both `WebClientResponseException` (org.springframework.web.reactive.function.client) and `RestClientResponseException` (org.springframework.web.client) extend `RestClientException` (the abstract superclass) but each is a sibling at the next level. Both expose:
- `getStatusCode().value()` → `int` HTTP status (HttpStatusCode interface)
- `getResponseBodyAsString()` → `String` body (same name, same signature)
- `getMessage()` → `String` (Throwable parent)

So the existing `matchesBadModelShape(RestClientResponseException)` body is structurally portable to `WebClientResponseException` — extract the shape-match into an `instanceof`-agnostic helper that takes the status int + body + message strings, or duplicate the predicate (4 lines).
