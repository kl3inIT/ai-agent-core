Build a call-count proxy over the per-file encode path (`FileStorage` read, Tika parse) and the
`AiUiSettingsResolver.resolveTaskFile*` singleton reads, and branch:
- If the proxy shows encode/settings already run at most once per `(conversationId, taskFileId)` per
  turn → ship the call-count REGRESSION ASSERTION that locks the good behavior; add NO new cache

  encoded `Media` (and/or the settings singleton read) per `(conversationId, taskFileId)` for the turn,
  evicted on attachment add/delete/TTL and on `AiSettingsChangedEvent(UI_SETTINGS)` (mirroring how the
  Plan 01 denylist evicts on `LlmExposureChangedEvent`).

Keep `PerTurnMediaInjectionTest` + budget/TTL tests unchanged. Preserve the per-turn-all + LRU
budget-cap semantics and the constrained-`DataManager` row load (never `UnconstrainedDataManager`/raw
JPQL on the LLM-steerable data path).

Purpose: Guarantee no in-turn re-serialization of the same task file, the cheapest correct way —
regression-lock where already-optimal, cache only where a real second encode exists.
Output: The proxy-first call-count test (branching to regression-lock or cache); a per-turn `Media`
memo ONLY if the proxy proves it necessary.

overlap with Plans 01/02/03 and reuses no symbol they create (it has its own `AiSettingsChangedEvent`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| task-file row load → LLM media injection | The `AiTaskFile` rows are loaded for a conversation and encoded into LLM-visible `Media`; the load must stay row-level-secured (constrained `DataManager`), and a stale media cache must not survive an attachment delete or settings change. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-11 | Information Disclosure | A per-`(conversationId, taskFileId)` media memo serving a deleted/expired attachment | mitigate (cache branch only) | If a cache is added, it is per-turn (wiped each turn) and evicted on attachment add/delete/TTL + `AiSettingsChangedEvent(UI_SETTINGS)`; the regression-lock branch adds no cache at all. |
| T-18-12 | Elevation of Privilege | Switching the row load to `UnconstrainedDataManager`/raw JPQL to "speed up" the encode path | mitigate | Acceptance criterion forbids any `UnconstrainedDataManager`/raw-JPQL token on the row load; the constrained `DataManager.load(...).query(...)` keeps row-level security in force. |
| T-18-13 | Tampering | Stale `AiUiSettings` (TTL/caps) memo after an admin edit | mitigate (settings-memo branch only) | A settings-read memo, if added, evicts on `@EventListener(AiSettingsChangedEvent)` guarded on `Kind == UI_SETTINGS` — admin edit visible next turn (PERF-05). |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | N/A — zero packages installed. |
