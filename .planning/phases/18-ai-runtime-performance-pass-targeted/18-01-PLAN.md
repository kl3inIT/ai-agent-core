<objective>
Memoize the exposure denylist app-wide inside `LlmExposurePolicy` (PERF-02): replace the per-call
`hiddenEntityNames()` agentstore SELECT with a single-sentinel-key `ConcurrentHashMap` +
`computeIfAbsent`, evicted via a new `@EventListener(LlmExposureChangedEvent)` `.clear()` — the exact
eviction twin of the shipped Phase 17 `RelatedWriteMetadataResolver`. Lower the
`ToolQueryCountBaselineTest` SELECT ceiling to reflect the eliminated per-call lookup, touching only
the constant at line 151. Ship the PERF-02 proxy set: a call-count spy ("one fetch reused until the
event, then exactly one refetch") and a source-scan invariant ("every exposure-derived cache
subscribes to `LlmExposureChangedEvent`").

This is the FOUNDATION plan — the denylist memo is the shared dependency that the per-turn
read-through (Plan 02, PERF-01) and the RAG filter (Plan 03, PERF-03) both reuse. It MUST land first.

Purpose: Eliminate the one agentstore SELECT per call from five internal call sites
(`getReadableSchema`, `canReadEntity`, `canCreate`, `canUpdate`, `getDenylistedEntityNames`) without
adding any new component, public API, or cache dependency, and without changing exposure/opacity
semantics.
Output: Memoized `LlmExposurePolicy` with event eviction; lowered baseline ceiling; two new pure-JUnit
proxy tests.

PERF-02 also covers the pure-metadata entity-name→`MetaClass` derivation (D-06). Per SPEC §Background
and RESEARCH, that derivation ALREADY resolves off the immutable Jmix metamodel (no agentstore SELECT,
security-independent), so the proxy-driven scope discipline (D-10) applies: this plan does NOT add a
redundant `ConcurrentHashMap` for it. If the metamodel lookup is shown to be already O(1)/cache-free in
the ToolQueryCountBaselineTest steady state, the lowered SELECT ceiling is itself the regression lock;
add a dedicated entity-name→`MetaClass` memo (no eviction, mirroring `RelatedWriteMetadataResolver`)
ONLY if Task 2 shows a per-call metadata SELECT in the steady-state count. Record which branch was
taken in the SUMMARY.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin denylist edit → Ai runtime | An admin's `AiExposureRule` change must become visible to the LLM-facing schema within one turn; a stale memo would leak a denied entity. |
| LLM tool call → exposure gate | The denylist is the entity-opacity surface; a wrong cached value could over- or under-expose entities. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Tampering | `LlmExposurePolicy` denylist memo outliving an admin edit | mitigate | `@EventListener(LlmExposureChangedEvent)` `.clear()` (D-05); `LlmExposureDenylistMemoTest` proves exactly-one-refetch after the event (admin edit visible next turn). |
| T-18-02 | Information Disclosure | A cache that silently never evicts (e.g. `@Cacheable` on a self-invoked private method) | mitigate | D-07: forbid `@Cacheable`; use in-bean `ConcurrentHashMap`; `ExposureCacheEventSubscriptionInvariantTest` asserts every exposure-derived cache subscribes to the event. |
| T-18-03 | Elevation of Privilege | Denylist memo shared app-wide reused across users | accept | The denylist is user-INDEPENDENT (exposure-derived, not role/user-specific); `AccessManager`/constrained `DataManager` remain authoritative for row-level access (D-08). App-wide reuse is correct by design; only an across-turn admin edit changes the verdict. |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | N/A — this plan installs zero packages (memoization over existing classes only); no `[ASSUMED]`/`[SUS]` package. |
