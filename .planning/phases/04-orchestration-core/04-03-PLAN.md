<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Chat caller → AuditAdvisor | Untrusted prompt text enters audit pipeline; promptHash protects against logging raw secrets while preserving correlation. |
| Tool delegate → ToolCallbackAuditDecorator | Tool may throw arbitrary Throwable; audit row must persist regardless. |
| AuditWriter → AuditListener (host SPI) | Host code can register listeners; one bad listener must not break audit or chat. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Information Disclosure | AuditAdvisor.hashPrompt | mitigate | Hash (SHA-256, first 64 hex) of prompt — never store raw prompt text in chat-level audit row. Raw text already lives in AiMessage (separately governed by Jmix entity ACLs). |
| T-04-03-02 | Tampering / Repudiation | AuditWriter | mitigate | REQUIRES_NEW boundary on AuditWriter ensures audit row commits independently of caller tx; tool rollback cannot retroactively erase the row (AUD-02). |
| T-04-03-03 | Denial of Service | AuditListenerFanOut | mitigate | Per-listener try/catch on `Throwable` prevents one host listener from crashing the chat thread or blocking other listeners (D-13). |
| T-04-03-04 | Elevation of Privilege | AuditAdvisor.resolveUserId | accept | Reflective `getUser().getKey()` extraction is read-only and falls back to "anonymous" on failure; no privilege change possible. |
| T-04-03-05 | Repudiation | ToolCallbackAuditDecorator | mitigate | PRE row written before tool execution AND POST row in `finally` — both rows survive tool throwable due to AuditWriter REQUIRES_NEW. |
</threat_model>
