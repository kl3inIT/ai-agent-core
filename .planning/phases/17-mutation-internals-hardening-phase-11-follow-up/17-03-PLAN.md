Replace the per-reference to-one FK load in `MutationAttributeBinder.coerceAttributeValue` (one
`dataManager.load(class).id(id).optional()` per reference — the N+1) with a two-pass design ON THE SAME BEAN
(no new collaborator, per D-06): a `prefetchReferences` pass collects all to-one FK ids per target class
across ALL rows and issues ONE constrained `DataManager.load(targetClass).ids(idCollection).list()` per class
(calling `enforceLlmRelationshipTargetExposure` + `enforceReadPermission` once per target class), returning a
prefetched reference map; and a `coerceAttributes` overload that binds from that map. The existing single-arg
`coerceAttributes` delegates through the same path with a one-element row list, giving create/update
single-call dedup with no separate branch (D-07).

(`FluentLoader.ids(java.util.Collection<?>)` alongside `ids(Object...)`), so `.ids(idCollection).list()` is the
locked signature — no varargs fallback needed (closes RESEARCH Open Question / A1).

Purpose: kill the bulk N+1 while preserving byte-identical error classification, failedRowIndex, and
full-batch rollback (MUT-16, locked by the existing partial-failure / relationship-exposure / error-translator
suites).
