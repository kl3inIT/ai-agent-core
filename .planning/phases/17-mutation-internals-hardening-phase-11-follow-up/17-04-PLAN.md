<objective>
Extract the fail-closed mutation gate sequence — currently hand-written inline in `createRecord`,
`updateRecord`, the shared `executeRelatedWrite` (add/remove), and `bulkSaveRecords` — into ONE canonical
`MutationGateChain` `@Component` with a single `execute(MutationRequest)` entry point that calls ordered,
named private gate methods (`enforceRole` -> `resolve` -> `authorize` -> `reserve` -> `coerce` -> `guard` ->
`save` -> `finalize`). Introduce a sealed `MutationRequest` hierarchy (`Create`/`Update`/`AddRelated`/
`RemoveRelated`/`Bulk`) that localizes the two real divergence points (the bulk per-row coerce/CrudEntityContext/
guard loop + SaveContext/bulkSave; the per-tool argumentsJson serializer + success-result shape). The five
`@Tool` methods become thin adapters. This is the highest-parity-risk piece and is isolated in its own wave.

This phase is a BEHAVIOR-FROZEN refactor: the catch ladder, error classification, audit rows, and idempotency
semantics must be byte-for-byte identical. The bulk-only fourth catch arm (`AccessDeniedException` ->
BLOCKED/`row_access_denied`, lines 1058-1067) MUST be preserved and applied ONLY for the `Bulk` variant; the
single-row tools keep their three-arm ladder. Per-invocation mutable state (`commitState`, `reservation`,
`failedRowIndex`, `startedAt`, `userUsername`, `metaClass`) MUST be method locals / a per-execute context
object — NEVER instance fields on the singleton chain.

Purpose: one canonical sequence for Phase 18's perf pass to touch, with the source-level ORDER invariant
enforced. Output: 2 new files + `BuiltInMutationTools` rewritten as adapters; the three Plan 01 MUT-15
assertions turn GREEN.
</objective>
