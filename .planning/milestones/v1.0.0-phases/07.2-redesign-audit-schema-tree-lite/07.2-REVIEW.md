# Phase 7.2: Code Review Report

**Reviewed:** 2026-04-24T18:00:51Z
**Depth:** standard
**Files Reviewed:** 45
**Status:** issues_found

## Summary

Reviewed the Phase 7.2 audit tree-lite changes with emphasis on retrieval audit wiring, `RunContext` ThreadLocals, `AiAuditEvent` persistence, security roles, list/detail views, Liquibase, and tests. The implementation has good defensive patterns around `REQUIRES_NEW` audit writes and `RunContext.clear()`, but there are two high-impact issues: the new audit changelog drops the previous audit table without migrating data, and streaming chat is not covered by the `CallAdvisor` audit root, causing streamed tool/retrieval audit rows to be orphaned or missing chat roots. Several UI/security access and filter correctness gaps should be addressed before release.

## Critical Issues

### CR-01: Audit Changelog Drops Existing Audit History

**File:** `ai-agent/ai-agent/src/main/resources/com/vn/agent/liquibase/agentstore-changelog/090-ai-audit-event.xml:8`
**Issue:** The first changeset drops `AI_AGENT_TOOL_CALL_AUDIT` whenever it exists, then creates the new `AI_AGENT_AUDIT_EVENT` table. This destroys existing audit history during upgrade, which is a data/audit integrity failure. Audit data is usually compliance-relevant and should not be silently discarded.
**Fix:** Replace the destructive drop with a migration path: create the new table, copy legacy rows into `AI_AGENT_AUDIT_EVENT` as `TOOL` rows with preserved IDs/timestamps/outcomes where possible, then drop or archive the legacy table only after successful copy. If legacy preservation is intentionally impossible, add an explicit opt-in precondition/property and document the irreversible data loss.

### CR-02: Streaming Calls Do Not Get Chat Root Audit Rows

**File:** `ai-agent/ai-agent/src/main/java/com/vn/agent/audit/AuditAdvisor.java:44`
**Issue:** `AuditAdvisor` implements only `CallAdvisor`. The streaming path uses `.stream().chatResponse()` in `DefaultChatServiceImpl`, so the call advisor does not wrap streamed turns. `DefaultChatServiceImpl.stream()` sets only the run ID, while the root audit ID is set exclusively by `AuditAdvisor` after `writeChatStart()`. As a result streamed turns do not create/finish a `CHAT` root row, and streamed tool/retrieval rows are written with `parentId == null` or may lose retrieval correlation.
**Fix:** Add streaming audit support by implementing the Spring AI streaming advisor contract or wrapping `stream()` explicitly with `writeChatStart()`/`writeChatFinish()` and `RunContext.setRootAuditId()` before subscribing to the advisor chain. Add a streaming integration test asserting one `CHAT` root plus child `TOOL`/`RETRIEVAL` rows share the same parent.

## Warnings

### WR-01: Retrieval Audit Rows Lose Conversation Foreign Key

**File:** `ai-agent/ai-agent/src/main/java/com/vn/agent/rag/advisor/AuditingDocumentRetriever.java:68`
**Issue:** Retrieval audit writes pass `conversationId` as `null`, even though `AuditWriter.writeRetrieval()` supports a conversation FK. This makes retrieval rows depend entirely on parent/root traversal for conversation correlation and leaves orphan retrieval rows unqueryable by conversation when the parent is absent, such as the streaming gap above or defensive out-of-chain calls.
**Fix:** Carry the conversation ID through `RunContext` or the advisor context alongside run/root IDs, then pass it to `writeRetrieval(parentId, runId, userUsername, conversationId, ...)`. Add a round-trip test that verifies `AiAuditEvent.conversation` is populated for retrieval rows.

### WR-02: Admin Role Does Not Grant Detail Dialog View Access

**File:** `ai-agent/ai-agent/src/main/java/com/vn/agent/security/AiAgentAdminRole.java:39`
**Issue:** The admin role grants the audit list view but omits `AiAgent_AiAuditEvent.detailDialog`, while the list opens that view through `DialogWindows`. Jmix view policies can deny opening views that are not explicitly granted, so administrators may see the audit list but fail when clicking a row/detail action.
**Fix:** Add `"AiAgent_AiAuditEvent.detailDialog"` to the admin `@ViewPolicy` and extend `AdminViewAccessTest` to assert the detail dialog is permitted.

### WR-03: Tree Filters Only Match Root Rows, Not Child Tool/Retrieval Rows

**File:** `ai-agent/ai-agent/src/main/java/com/vn/agent/view/audit/AiAuditEventListView.java:159`
**Issue:** The base query is `e.parent is null`, but `toolFilter` and `outcomeFilter` add predicates against root fields (`e.eventName`, `e.outcome`). Tool names and many outcomes live on child `TOOL`/`RETRIEVAL` rows, so filtering by a tool name or child outcome can return no roots even when matching child events exist.
**Fix:** Filter roots with `exists` subqueries over children, for example `exists (select c from ai_AiAuditEvent c where c.parent = e and c.eventName = :tool)`, and similarly for child outcomes. Keep root predicates only for root-only filters.

### WR-04: Hardcoded Database Credentials in Application Properties

**File:** `jmix-app/src/main/resources/application.properties:3`
**Issue:** The main app properties contain concrete PostgreSQL usernames/passwords for both `main` and `agentstore` datasources. This risks credential leakage and encourages deploying with static shared credentials.
**Fix:** Replace the passwords with environment-backed placeholders such as `main.datasource.password=${MAIN_DB_PASSWORD:}` and `agentstore.datasource.password=${AGENTSTORE_DB_PASSWORD:}`, then keep developer defaults in a local ignored `.env` file.

## Info

### IN-01: Raw Vaadin Row Listener Bypasses Jmix Event-Wiring Convention

**File:** `ai-agent/ai-agent/src/main/java/com/vn/agent/view/audit/AiAuditEventListView.java:99`
**Issue:** The list view uses `auditsDataGrid.addItemClickListener(...)` directly. Project conventions prefer official Jmix event wiring via `@Subscribe`, `@Supply`, or `@Install` when expressible, to keep lifecycle and DI behavior consistent.
**Fix:** Move the row-click handling to an official Jmix-supported subscription/handler if available for `TreeDataGrid`, or document why the raw Vaadin listener is required.

### IN-02: Tool Error Class Stores Fully Qualified Names Unlike Chat Errors

**File:** `ai-agent/ai-agent/src/main/java/com/vn/agent/audit/ToolCallbackAuditDecorator.java:148`
**Issue:** Chat audit stores `t.getClass().getSimpleName()`, but tool audit stores `t.getClass().getName()`. This makes `ERROR_CLASS` inconsistent across audit kinds and can expose package names that the chat audit deliberately avoids.
**Fix:** Use `t.getClass().getSimpleName()` for tool audit rows as well, unless fully qualified class names are explicitly required for tool diagnostics.
