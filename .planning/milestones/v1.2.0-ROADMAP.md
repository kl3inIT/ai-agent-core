# Milestone v1.2.0: Operator Experience & Runtime Performance

**Status:** ✅ SHIPPED 2026-06-12
**Phases:** 15–18 (Phase 19 deferred — see below)
**Total Plans:** 25 (6 + 9 + 5 + 5)

## Overview

Layered four near-independent feature areas onto the shipped v1.1 agent harness with
effectively zero new runtime dependencies: a third right-sidebar chat surface with
in-chat observability, an admin model picker + three-tier config-knob migration,
mutation-internals hardening (Phase 11 follow-up), and a targeted AI-runtime
performance pass. The hard ordering constraint — **Phase 17 (mutation-internals
hardening) before Phase 18 (perf pass)** — was honored so the perf pass refactored the
consolidated `MutationGateChain` + shared batch-FK load rather than a duplicated
sequence.

**Voice Input was descoped from this milestone.** Phase 19 (Chat Voice Input — Soniox
STT + OpenAI fallback) was never started; it is moved back to the ROADMAP Backlog as
Phase 999.2 for a future milestone. The milestone name was changed from "Operator
Experience, Voice Input & Runtime Performance" to "Operator Experience & Runtime
Performance" to match what actually shipped.

## Phases

the shipped `FULL_ROUTE` and `HEADER_BUTTON` surfaces, and can see what the agent is

### Phase 17: Mutation-Internals Hardening (Phase 11 follow-up)

*(Was Phase 18 before the 2026-05-13 Phase 16+17 merge. Promotes Backlog 999.1.)*

**Goal**: The fail-closed mutation gate sequence is extracted into one canonical
`MutationGateChain` component (with the four mutation `@Tool` methods and
`bulk_save_records` as thin adapters), to-one FK references are batch-loaded during
attribute binding via a single constrained `DataManager` `IN(...)` per target class, and
related-write metadata resolution is memoized — with behavior byte-for-byte identical to
v1.1 so the Phase 9/10/11 mutation test suites pass unchanged.
**Depends on**: Nothing hard. **HARD CONSTRAINT: must precede Phase 18.**
**Requirements**: MUT-15, MUT-16, MUT-17, MUT-18
**Plans**: 5 plans

Plans:

- [x] 17-01: Wave-0 structural test seams — extend `MutationToolInvariantsTest` (gate-order/reflection + MUT-16 forbidden-token scan), new `RelatedWriteMetadataMemoTest`, new `MutationFkBatchLoadQueryCountTest` + agentstore FK fixture
- [x] 17-02: MUT-17 — memoize `RelatedWriteMetadataResolver` via `ConcurrentHashMap` + record `Key` + `Result` holder + package-private `computeSupported` seam (no eviction)
- [x] 17-03: MUT-16 — two-pass FK batch-load in `MutationAttributeBinder` (`prefetchReferences` + `coerceAttributes(prefetched)`, one constrained `.ids()` per target class; byte-identical error parity)
- [x] 17-04: MUT-15 — extract canonical `MutationGateChain` `@Component` (sealed `MutationRequest` + ordered named gates, no `@Transactional`) + reduce the five `@Tool` methods to thin adapters
- [x] 17-05: [BLOCKING] MUT-18 — full Phase 9/10/11 mutation suite + `AgentToolCallbacksDefaultConfigTest` pass with zero test-body edits + git-diff audit of the test tree

**Details:** Canonical `MutationGateChain` `@Component` (`AiAgentMutationRole` → exposure →
`AccessManager` entity+attribute → `AiMutationIntent` idempotency → `MutationGuard` SPI →
`@Transactional` save) with `create_record` / `update_record` / `add_related_record` /
`remove_related_record` / `bulk_save_records` as thin adapters; source-level invariant
test enforces gate order and asserts every gate throws before the transactional save
(only `MutationSaveExecutor.save` carries `@Transactional`). Constrained batch FK loads
(never `UnconstrainedDataManager`, never raw JPQL — row-level security preserved).
Memoized related-write metadata (immutable Jmix metamodel, no eviction). MUT-18 parity
HOLDS — byte-for-byte behavior-identical, no test-body edits. Completed 2026-05-31.

### Phase 18: AI-Runtime Performance Pass (targeted)

binding/save, media/attachment injection, RAG retrieval/filter building, and

**Requirements**: PERF-01, PERF-02, PERF-03, PERF-04, PERF-05

## Milestone Summary

**Decimal / renumbered Phases:**

- Former Phase 16 "Admin Model Management" + Phase 17 "Admin Config-Knob Migration" merged
  into the new Phase 16 on 2026-05-13 (shared `AiParameters`/`AiUiSettings` schema).
- Former Phases 18/19/20 renumbered to 17/18/19 after the merge.

**Key Decisions:**

- Decision: `SIDEBAR` is a third surface over the SAME `ChatPanelFragment` (no second chat
  backend/memory). Rationale: cross-surface continuity + zero duplication.
- Decision: In-chat observability is driven by the existing `StreamingEvent` flux +
  `AiAuditEvent` tree — no new persisted "turn" entity. Rationale: no parallel state store.
- Decision: Three-tier knob taxonomy (runtime-editable / boot read-only / secret
  indicator-only); secrets never editable or displayed. Rationale: SEC-08 fail-closed.
- Decision: Model validity checked at first use (graceful fallback), not at save time.
  Rationale: avoid blocking admin saves on transient provider reachability.
- Decision: Single canonical `MutationGateChain` with `@Transactional` only on
  `MutationSaveExecutor.save`; every gate throws before the save. Rationale: fail-closed
  byte-for-byte parity with v1.1 (MUT-18).
- Decision: Perf caches wire to an invalidation hook — `LlmExposureChangedEvent` for
  exposure-derived, the Phase 16 `AiSettingsChangedEvent` for settings; user/role/exposure
  data stays per-`RunContext` (one turn). Rationale: correctness over raw speed.
- Decision: Voice Input (Phase 19) descoped → Backlog 999.2; milestone renamed to drop
  "Voice Input". Rationale: ship the four completed feature areas; STT never started.
