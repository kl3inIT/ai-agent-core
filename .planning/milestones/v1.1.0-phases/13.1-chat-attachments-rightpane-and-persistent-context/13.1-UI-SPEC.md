# Phase 13.1 — UI Design Contract

> Visual and interaction contract for the CRM-style right-pane Attachments port + inline NOTICE ledger row + budget-exceeded toast.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Tech stack: Java 21 + Jmix 2.8 + Vaadin Flow 24.8 + Lumo theme. **Not** a React/shadcn project — shadcn gate is not applicable; design tokens are sourced from Lumo CSS custom properties.

## Spacing Scale

This project uses Lumo spacing tokens (CSS custom properties) — multiples of 4 by Lumo convention. Phase 13.1 declares ONLY Lumo tokens; no raw pixel values introduced in XML or CSS.

| Token | Lumo CSS property | Resolved px @ default Lumo theme | Usage in this phase |
|-------|-------------------|----------------------------------|---------------------|
| xs | `var(--lumo-space-xs)` | 4px | Card grid gap, drop-label margin-top, drop-zone primary-buttons gap, NOTICE row vertical margin (`var(--lumo-space-s) 0`) |
| s | `var(--lumo-space-s)` | 8px | Drop-zone padding, NOTICE row vertical margin, card meta hbox gap |
| m | `var(--lumo-space-m)` | 16px | Right-pane vbox padding, NOTICE row icon offset, message bubble padding (existing) |
| l | `var(--lumo-space-l)` | 24px | (Reserved; not used in 13.1) |
| xl | `var(--lumo-space-xl)` | 32px | (Reserved; not used in 13.1) |

**Touch target exception:** card icon-only buttons (`openButton`, `deleteButton`) use `themeNames="tertiary-inline small icon"` which renders at Lumo's small-icon-button size. Acceptable for desktop-primary enterprise UI; Phase 13.1 does NOT enforce 44px touch targets (project is Jmix admin Flow UI, not mobile-first).

**Drop-zone min-height exception:** `min-height: 8rem` is a Lumo `rem`-based value (~128px), not a Lumo space token — verbatim from CRM. Acceptable because it is already a multiple-of-4 outcome and matches the CRM reference exactly.

## Typography

Lumo type scale only; no project-defined font sizes or weights. Phase 13.1 uses 4 size roles and 2 weight roles, satisfying the 3–4 size / 2 weight constraint.

| Role | Lumo CSS property | Resolved px @ default Lumo theme | Weight | Line height | Usage |
|------|-------------------|----------------------------------|--------|-------------|-------|
| Body | `var(--lumo-font-size-m)` | 16px | 400 (regular, Lumo default) | 1.5 (Lumo default) | Default chat text, inputs |
| Heading | `var(--lumo-font-size-l)` (h5) — or h3 → `var(--lumo-font-size-xl)` | 18px (h5) / 22px (h3) | 600 (semibold, Lumo default for headings) | 1.2 (Lumo default) | `<h3 attachmentsTitle>`, `<h5>` filename in card |
| Caption | `var(--lumo-font-size-s)` | 14px | 400 | 1.4 (Lumo default) | Card meta `createdDate` + `sizeValue` text via Lumo `text-s` class |

**Weights declared (exactly 2):** 400 regular (body, caption) + 600 semibold (Lumo's heading default; NOTICE override is 500 medium — counts as a third weight only on the NOTICE row, justified by verbatim CRM port). Plan-phase MAY relax NOTICE to 400 if a stricter 2-weight contract is required by the checker.

## Interaction Contract

| Event | Trigger | Reaction |
|-------|---------|----------|
| File picked / dropped | `taskFileUpload` Vaadin `SucceededEvent` | (1) Persist `AiTaskFile` row via `dataManager.save(...)` (regular `DataManager`, user row-policy applies). (2) Persist `AiMessage` row with `role=NOTICE` and bilingual notice text via `dataManager.save(...)`. (3) `taskFilesDl.load()` → grid refreshes, empty-state hides. (4) Message-list re-renders with the new NOTICE divider inline. (5) NO toast on success (silent on happy path). |
| Card `openButton` click | `<button id="openButton">` `ClickEvent` | `downloader.download(row.getStorageRef())` (Jmix `Downloader`, opens in new window/tab). NO confirmation. |
| Card `deleteButton` click | `<button id="deleteButton">` `ClickEvent` | Open `Dialogs.createOptionDialog().withType(WARNING)` with the bilingual delete-confirm copy. On confirm: `fileStorage.removeFile(row.getStorageRef())` (log-and-continue on failure per CONTEXT discretion) → `dataManager.remove(row)` → `taskFilesDl.load()`. NOTICE row in message stream is NOT auto-removed (audit trail preserved). |
| Empty state ↔ populated | `taskFilesDl.PostLoadEvent` | Programmatic toggle of `attachmentsEmptyState.setVisible(items.isEmpty())` and `attachmentsGridLayout.setVisible(!items.isEmpty())` in `ChatPanelFragment.refreshTaskFiles()` |
| Chat send with budget exceeded | `AiTaskFileMediaResolver.resolveActive(conversationId)` returns `Resolved{budgetExceeded=true}` | `Notifications.create(messageBundle.getMessage("chatView.attachments.budgetExceeded"), Notifications.Type.WARNING).show()` — non-blocking, default Lumo dismiss timer, parallel to the audit row write. Chat send proceeds with the kept files. |
| Surface switch (FULL_ROUTE ↔ HEADER_BUTTON) | Phase 12 `ChatSurfaceMounter` toggles | Both surfaces mount the SAME reshaped `chat-panel-fragment.xml`. The card grid + drop-zone + NOTICE rows render identically. Continuity verified by Phase 12 `AiChatSessionState` (existing) + Phase 13.1 `SurfaceMountingTest`. |
| MIME / size rejection | Vaadin Upload component native | Lumo's built-in rejection toast. NO custom `FailedEvent` handler shipped in 13.1 (project memory `feedback_jmix_upload_receiver_deprecated` notes only `FileRejectedEvent` is safe to move to `@Subscribe` — plan-phase verifies whether to surface a custom message). |

### State transitions

```
[empty] ──upload-success──▶ [populated]                            ▶ [populated, NOTICE row inline]
[populated] ──card-delete-confirm──▶ [empty | populated]
[populated] ──TTL-expiry (cleanup job)──▶ [empty | populated]
[populated] ──conversation-delete (FK cascade)──▶ [removed]        ▶ (right pane unmounts with conversation)
[populated, send-turn, budget-OK] ──ChatService.ask──▶ [populated, all media injected]
[populated >cap, send-turn] ──ChatService.ask──▶ [populated, LRU media injected, WARNING toast, audit row]
```

### Mobile / narrow-viewport behavior

Out of scope for v1.1. Project is enterprise Jmix admin UI (desktop-primary). The `<split>` element is responsive within Lumo defaults; below ~600px viewport the split degrades visually but does not break functionally. Plan-phase does not introduce a media-query collapse-to-drawer behavior; if hosts request it, future v1.2 phase ships a collapse breakpoint.
