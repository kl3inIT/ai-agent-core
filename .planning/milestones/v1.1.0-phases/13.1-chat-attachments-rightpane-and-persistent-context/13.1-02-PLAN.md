<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Resolver entry (called from chat service) | Receives a conversationId from the chat path; conversationId came from authenticated user state earlier — NOT untrusted directly. |
| Audit write boundary | Resolver invokes AuditWriter on overflow; AuditWriter has its own REQUIRES_NEW transaction so a write failure cannot poison the chat turn. |
| User row-level policy | Resolver intentionally uses `DataManager` (NOT `UnconstrainedDataManager`) so the existing `AiAgentUserRowLevelRole.taskFile()` predicate `{E}.userUsername = :current_user_username` continues to filter cross-user reads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13.1-05 | Information Disclosure | Cross-user attachment leak via `resolveActive` | mitigate | Resolver uses `DataManager` so row-level policy applies; load query filters by `e.conversation.id` AND the row-level `userUsername` predicate runs implicitly. NO `UnconstrainedDataManager` (research Common Operation 3 + memory `feedback_jmix_unconstrained_for_system_writes`). |
| T-13.1-06 | Denial of Service | Unbounded `Media` payload sent to LLM exhausts model context window | mitigate | Per-turn caps default 10 files / 50 MB total; rows beyond the cap are dropped in DESC order (LRU). Caps are configurable per-deployment. |
| T-13.1-07 | Repudiation | Operator cannot prove which attachments the model saw on a given turn | mitigate | `task_file_budget_exceeded` audit row records `keptRows`, `droppedRows`, total + kept + dropped bytes, both cap values — sufficient to reconstruct what the LLM received. Reuses `AuditWriter.writeToolCall` (no new AuditKind, per SPEC constraint). |
| T-13.1-08 | Tampering | Audit write failure silently masks a budget-overflow event | accept | Audit failure is `log.warn`-and-continue; budget enforcement still applied to the returned `Media` list. Operator alerting on `WARN` log lines is out-of-scope for this phase. Mirrors `auditDenial` precedent at DefaultChatServiceImpl.java:763-771. |
</threat_model>
