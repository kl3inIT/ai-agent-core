## AiTaskFileProperties.java New Shape

| Field                    | Type   | Default       | Sentinel                                |
|--------------------------|--------|---------------|------------------------------------------|
| `ttlSeconds`             | `long` | `86_400L` (24h) | `-1` = no TTL (cleanup job skips purge) |
| `maxFileSizeBytes`       | `long` | `104_857_600L` (100 MB) | n/a (unchanged)                  |
| `perTurnMaxFiles`        | `int`  | `10`          | `-1` disables file-count cap            |
| `perTurnMaxTotalBytes`   | `long` | `52_428_800L` (50 MB) | `-1` disables byte cap            |

The prior `Duration ttl = Duration.ofHours(1)` field and its `getTtl/setTtl` accessors are gone, along with the `java.time.Duration` import. `@ConfigurationProperties(prefix = "ai-agent.task-file")` is preserved.

## AiTaskFileCleanupJob.java Sentinel Path

`deleteExpiredTaskFiles()` now reads `taskFileProperties.getTtlSeconds()` first. When the value is `-1L` an `AtomicBoolean.compareAndSet(false, true)` guard makes the job log once at INFO (`"AiTaskFile TTL disabled (ttl-seconds=-1); cleanup job skipping TTL purge"`) and return without scanning the table. Otherwise the existing `repository.deleteAllExpired(OffsetDateTime.now())` path runs unchanged. `@Scheduled(cron = "0 0 * * * *")` is preserved.
