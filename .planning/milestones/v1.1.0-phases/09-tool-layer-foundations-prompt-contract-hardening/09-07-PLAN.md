# Plan 09-07: Close UAT Entity-Name Tool-Call Contract Gap

## Goal

Close the UAT gap where the model selected `jmixapp_Customer` even though the baseline exposed `Customer (Khach hang)`. The fix should make the LLM-facing contract explicit: user-facing replies use labels, but tool arguments named `entityName` must use the exact entity `name` string shown in `agent.entities` or returned by `list_entities`; the model must not invent or add host prefixes.

## Gap Source

- `.planning/phases/09-tool-layer-foundations-prompt-contract-hardening/09-UAT.md`
- `.planning/debug/prompt-entity-name-contract.md`

## Must Haves

1. The composed system prompt contains a clear rule for `entityName` tool arguments: use the exact entity name from `agent.entities` or `list_entities`, and do not infer/add application prefixes.
2. `AgentSystemPromptRules.PROMPT_RULES` no longer includes a concrete hard-coded `jmixapp_Customer` example that can prime host-prefix invention.
3. Every `entityName` `@ToolParam` description in `BuiltInDataTools` uses exact-name-from-inventory wording instead of vague "Jmix entity name" or hard-coded `jmixapp_*` examples.
4. Existing user-facing vocabulary rules and `UnknownEntityHints` wording remain intact.
5. Regression tests lock the new prompt/tool metadata contract.
