## 1. System Classification

**System Type:** Hybrid - conversational assistant UI surface plus deterministic UI/session orchestration and a small content-generation subtask for conversation titles.

**Description:**
Phase 12 exposes the existing Jmix AI Copilot chat runtime through two admin-toggleable surfaces: the full route (`ChatView`) and a header button that opens a non-modal Jmix `DialogWindow` containing the same `ChatPanelFragment`. The LLM-facing runtime stays Spring AI `ChatClient`; the new AI work is the asynchronous `AiConversationTitleService`, which generates a short locale-aware conversation title after the first assistant reply without blocking the chat path. Good behavior means a user can move between enabled surfaces without losing the active conversation, admins can control surfaces through normal Jmix security and settings, and title generation produces useful labels while never changing permissions, blocking replies, or clobbering user edits.

**Critical Failure Modes:**
1. **Conversation fork across surfaces** - opening the dialog or route creates a second `AiConversation` or loses JDBC chat-memory continuity for the same user session.
2. **UI/security parity break** - disabled surfaces, hidden routes, admin settings, or header-button visibility diverge from Jmix `AccessManager`, menu, view, and entity policies.
3. **Dialog lifecycle disrupts chat** - route navigation, dialog toggle, detach, or close cancels the wrong stream, leaks a dialog handle, or leaves the UI stuck while `CancellationRegistry` state is stale.
4. **Auto-title clobbers user intent** - asynchronous title generation overwrites a manually edited title, uses the wrong locale, leaks prompt/tool internals, or surfaces failures to the chat user.
5. **Admin rollout drift** - `AiUiSettings` defaults, single-row persistence, menu visibility, and route gating fall out of sync so hosts cannot predict which chat surfaces are available.

## 1b. Domain Context

**Industry Vertical:** Developer tooling / enterprise internal applications - a horizontal Jmix AI add-on embedded into host systems of record.

**User Population:** Authenticated Jmix operators who use chat while working in business screens; admin operators who configure AI UI availability; Jmix/security architects who validate that the add-on behaves like a normal Jmix client.

**Stakes Level:** High.

**Output Consequence:** The visible chat surface can influence operator decisions and may expose mutation-capable tools shipped in earlier phases when enabled by a host. The auto-generated title becomes persistent UI/audit context for later reviews. Incorrect surface or title behavior can hide AI access, duplicate conversations, confuse audit trails, or expose sensitive prompt/tool vocabulary.

```
Good: A conversation started in one enabled surface reopens in the other surface with the same
      conversation id, same message history, same JDBC memory rows, and no duplicate conversation.
Bad:  A route/dialog switch starts a new conversation, drops a message, replays the wrong history,
      or leaves two active fragment instances competing for one stream.
Stakes: Critical
Source: Phase 12 TEST-14, SURF-04/SURF-05, and Jmix operator workflow expectations.
```

```

      menu, direct route, or accidental button render.

Stakes: Critical
```


### Known Failure Modes in This Domain

- **Surface switch creates split history:** dialog opens with `conversationId=null` even though the Vaadin session has an active route conversation, producing two `AiConversation` rows for one user task.
- **Detached fragment cancels the wrong stream:** adding session listeners without correct unsubscribe or run-id ownership causes route detach to cancel a dialog stream that should continue.
- **Security-visible UI mismatch:** the header button is rendered from a UI-tree hook without applying `UiShowViewContext`, or `FULL_ROUTE` direct navigation remains possible after the admin disabled it.
- **Asynchronous title race:** user manually renames the conversation while the title job is running; the async save overwrites the manual title because it did not reload and recheck the default sentinel.
- **Locale and vocabulary drift in titles:** the title prompt defaults to English for Vietnamese conversations, or the model summarizes with internal names/tool names that earlier prompt-hardening phases prohibit in user-visible text.

### Regulatory / Compliance Context

No single sector regulation applies to the add-on as a horizontal Jmix component. Compliance obligations are inherited from the host application and deployment domain.

Directly relevant controls for this phase are least-privilege UI exposure, audit completeness, data minimization in generated titles, and no unnecessary disclosure of personal or confidential data. GDPR or similar privacy law may apply if host chat content includes personal data and generated titles persist that data. SOC 2 / ISO-style reviews will care about predictable admin configuration, access-control parity, and durable audit evidence.

## 2. Framework Decision

**Selected Framework:** Spring AI 1.1.4 with existing Jmix Flow UI / Vaadin Flow integration.

**Version:** Spring AI 1.1.4, Jmix 2.8, Vaadin Flow 24.x as supplied by Jmix.

**Rationale:**
Spring AI is already the shipped LLM framework for this add-on: `ChatClient`, advisor chain, tool callbacks, JDBC chat memory, RAG, and structured-output helpers are in production code. Phase 12 does not need a new agent runtime; it needs a small, isolated Spring AI title-generation call plus careful Jmix/Vaadin UI/session orchestration around the existing chat service. Keeping Spring AI avoids rewriting audit, memory, tool-calling, and guard behavior, while Jmix remains the authority for UI composition, security, data access, and localization.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|-------------------|
| LangChain4j | Credible Java option, but it would create a parallel model/tool/memory abstraction beside already-shipped Spring AI code. |
| Raw OpenAI/OpenRouter SDK | Would bypass Spring AI `ChatClient`, advisors, memory, structured output, retries, and existing OpenAI-compatible provider wiring. |
| OpenAI Agents SDK | Python/TypeScript agent framework; overkill for a Java/Jmix UI surface and would not integrate naturally with Jmix security/session state. |
| LangGraph / LangChain Python | Incompatible with the Java add-on packaging and unnecessary because Phase 12 is not a stateful autonomous workflow. |

**Vendor Lock-In Accepted:** Partial. The project accepts framework-level Spring AI lock-in because earlier phases already depend on it. Model-provider lock-in remains low: production uses Spring AI `ChatModel`/`ChatClient` and OpenAI-compatible configuration, with OpenRouter as a configurable default rather than a hardcoded provider.

### Entry Point Pattern

Production chat remains on the existing `DefaultChatServiceImpl`. The new title-generation call must be isolated from the main advisor/tool chain and must be fail-silent.

```java
public Optional<String> generateTitle(AiConversation conversation, List<AiMessage> contextMessages) {
    String prompt = titlePromptRenderer.render(conversation, contextMessages);

    try {
        String rawTitle = chatClientBuilder
                .build()
                .prompt()
                .system(titleSystemPrompt)
                .user(prompt)
                .options(OpenAiChatOptions.builder()
                        .model(properties.resolvedModelId())
                        .temperature(0.0)
                        .maxTokens(32)
                        .build())
                .call()
                .content();

        return titleSanitizer.clean(rawTitle);
    } catch (RuntimeException exception) {
        log.warn("auto-title generation failed conversationId={}", conversation.getId(), exception);
        auditTitleFailure(conversation, exception);
        return Optional.empty();
    }
}
```

Planner note: before implementation, verify whether the injected object should be the existing `ChatClient` or a cloned `ChatClient.Builder`. If a builder is used, ensure it does not inherit default tools/advisors. If only the current `ChatClient` bean is available, prefer `.prompt()` with a title-specific system prompt and no `.toolCallbacks(...)`, then explicitly test that no tool callbacks/advisors fire during title generation.

### Vaadin UI Init / Navigation Pattern

Vaadin registers UI lifecycle hooks through a `VaadinServiceInitListener`.

```java
@Component
public class ChatSurfaceMounter implements VaadinServiceInitListener {

    @Override
    public void serviceInit(ServiceInitEvent event) {
        event.getSource().addUIInitListener(uiInitEvent -> {
            UI ui = uiInitEvent.getUI();
            ui.addAfterNavigationListener(this::afterNavigation);
            mountWhenAppLayoutAvailable(ui);
        });
    }

    private void afterNavigation(AfterNavigationEvent event) {
        refreshSurfaceVisibility(event.getLocation());
    }
}
```

Use the first `AfterNavigationEvent` as the fallback mount tick if the `AppLayout`/`StandardMainView` is not attached during `UIInitEvent`.

### Common Pitfalls

1. **Using raw Vaadin `Dialog` for the header surface.** It bypasses the chosen Jmix `DialogWindow` lifecycle and reintroduces the dropped floating-launcher stacking problem.
2. **Mounting the header button before `AppLayout` exists.** Register at `UIInitEvent`, but fall back to the first `AfterNavigationEvent` when the UI tree is not ready.
3. **Treating dialog close as conversation close.** Closing the dialog hides UI only; only "new chat" clears `AiChatSessionState.currentConversationId`.
4. **Storing active run state in `AiChatSessionState`.** `CancellationRegistry` remains the source of truth for active runs; session state carries conversation id and listeners only.
5. **Letting title generation inherit chat tools/advisors accidentally.** Title calls should not call tools, perform RAG, or mutate chat memory. Add a regression test.
6. **Async event before durable message commit.** Publish the title eligibility event only after assistant message persistence; prefer `@TransactionalEventListener(phase = AFTER_COMMIT)` if the implementation path is transactional.
7. **Using Spring `MessageSource` in new Jmix view code.** New code should inject `io.jmix.core.Messages` / `MessageBundle` per project convention.

## 4. Implementation Guidance

**Model Configuration:**
Main chat stays governed by active `AiParameters` and `Overrides`. Auto-title uses a constrained per-call override:

```java
OpenAiChatOptions titleOptions = OpenAiChatOptions.builder()
        .model(properties.resolvedModelId())   // default: active profile model
        .temperature(0.0)
        .maxTokens(32)
        .build();
```

Keep title model override optional. If unset, use the same effective model as the chat profile. Never hardcode an API key or provider base URL; use existing Spring AI/OpenRouter configuration.

**Core Pattern:**

1. `DefaultChatServiceImpl` persists the assistant response.
2. After persistence is durable, publish `ConversationTitleEligibleEvent` when the conversation has exactly one assistant message and the title is still the default sentinel.
3. `AiConversationTitleService` consumes asynchronously.
4. It loads recent user/assistant context with `UnconstrainedDataManager`, renders a locale-aware title prompt, performs a low-temperature Spring AI call, sanitizes the result, reloads the conversation, rechecks title is still default, saves the new title, and writes an audit row.
5. Any title failure writes WARN/audit and returns. It must not propagate into the chat reply path.

**Tool Use:**
Auto-title uses no tools and no RAG. It must not call `AgentToolCallbacks`, must not pass `ChatMemory.CONVERSATION_ID`, and must not inherit tool-calling advisor behavior in a way that causes tool invocation. Tests should use mocks/spies to assert title generation does not call `AgentToolCallbacks.callbacksFor(...)`.

**State Management:**

- `AiChatSessionState` (`@VaadinSessionScope`) owns `currentConversationId` and listener registration.
- `AiChatUIState` (`@UIScope`) owns the current `DialogWindow<ChatDialogView>` handle.
- `ChatPanelFragment.setConversationId(UUID)` remains the shared fragment API.
- `ChatPanelFragment.onAttach` registers with session state; `onDetach` unregisters and preserves current `CancellationRegistry` behavior.
- `ChatSurfaceMounter` re-reads `AiUiSettings` on UI init and each navigation. No cache for Phase 12.
- `AiUiSettingsService` uses a fixed singleton UUID and `UnconstrainedDataManager` for ensure-default/load.

**Context Window Strategy:**
Title generation should use a tight context window, independent from full chat memory:

- Include the first user message and the first assistant reply at minimum.
- Cap at `ai-agent.conversation-title.max-context-messages`, default 6.
- Strip or summarize tool-result markdown before title generation; title prompt should not need raw tool payloads.
- Bound output with `maxTokens(32)` and post-sanitize to 80 characters.
- Reject blank output, the default sentinel, quote-only output, and provider/tool/internal names caught by existing scanner patterns.

**Transaction / Event Boundary:**
Use one of these implementation shapes:

```java
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
@Async("aiConversationTitleTaskExecutor")
public void onTitleEligible(ConversationTitleEligibleEvent event) {
    titleService.generateAndPersist(event.conversationId());
}
```

or publish only after the existing save method has completed. The planner must choose the simpler path that matches current `DefaultChatServiceImpl` transaction boundaries and prove it with `AiConversationTitleServiceTest`.

**Jmix UI Contracts:**

- `ChatDialogView` is a `StandardView`, no entity binding, XML descriptor with `<fragment class="...ChatPanelFragment"/>`.
- `AiUiSettingsDetailView` is a `StandardDetailView<AiUiSettings>` with singleton-load override.
- Use `@Subscribe`, `@Install`, and XML descriptors for Jmix view wiring; avoid raw `addClickListener(...)` when `@Subscribe` works.
- All visible text goes through root `messages.properties` and `messages_vi.properties`.
- New entity instantiation uses `Metadata.create()` or `DataManager.create()`, not constructors.

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic

Production code is Java/Spring AI, so the primary structured-output type should be a Java record plus `BeanOutputConverter` or `ChatClient.call().entity(...)`. The Pydantic model below is for the eval harness or an optional offline title-quality judge, satisfying the cross-language AI-spec contract while keeping production Java-native.

```python
from pydantic import BaseModel, Field, field_validator


class ConversationTitleCandidate(BaseModel):
    title: str = Field(min_length=3, max_length=80)
    language: str = Field(pattern="^(en|vi)$")
    contains_internal_vocabulary: bool = False
    confidence: float = Field(ge=0.0, le=1.0)

    @field_validator("title")
    @classmethod
    def title_must_be_clean(cls, value: str) -> str:
        cleaned = value.strip().strip("\"'").rstrip(".")
        if cleaned.upper() == "NEW_CONVERSATION":
            raise ValueError("default sentinel is not a valid title")
        forbidden = ["find_records", "list_entities", "describe_entity", "RETRIEVAL", "ai_Ai"]
        if any(token in cleaned for token in forbidden):
            raise ValueError("title contains internal vocabulary")
        return cleaned
```

Java production equivalent:

```java
record ConversationTitleCandidate(
        @JsonProperty(required = true) String title,
        @JsonProperty(required = true) String language,
        boolean containsInternalVocabulary,
        double confidence) {
}

ConversationTitleCandidate candidate = chatClient.prompt()
        .system(titleSystemPrompt)
        .user(titleUserPrompt)
        .options(titleOptions)
        .call()
        .entity(ConversationTitleCandidate.class);
```

Retry policy:

- Retry once for parse/validation failure only.
- Do not retry access, rate-limit, cancellation, or provider-auth failures.
- Log model, conversation id, attempt count, and sanitized failure class.
- After retry exhaustion, audit `outcome=ERROR` and leave the existing title unchanged.

### Async-First Design

Use streaming for the user chat path because users need token-by-token feedback and a stop button. Use a complete `.call()` for title generation because a title must be sanitized and saved atomically after the full response is available.

Do not block a Vaadin UI thread waiting for the title job. The title event runs on a bounded async executor, and UI refresh is opportunistic: the next data reload or listener callback can display the generated title.

Common mistake: publishing an async title event before the assistant message transaction is durable. The title job then races the message save and may title an incomplete conversation.

### Prompt Engineering Discipline

- Keep title system prompt separate from user conversation content.
- Tell the model exactly what to return: one short title, no quotes, no trailing punctuation, no tool/provider/entity names.
- Include the locale instruction explicitly: "Return Vietnamese for Vietnamese conversation content; otherwise English."
- Do not include raw tool-result JSON unless a title genuinely needs it; summarize visible user/assistant text instead.
- Set `temperature=0.0` and `maxTokens=32`; do not leave output unbounded.

### Context Window Management

The title generator does not need the whole conversation. Use the first user turn plus the first assistant reply, optionally up to the configured max recent messages. Strip markdown citations/tool event details before prompt assembly. For the main chat surface, preserve the existing Spring AI JDBC memory and RAG top-k controls; Phase 12 must not add hidden summarization or compaction behavior.

### Cost and Latency Budget

Operational targets:

- Header-button visibility refresh: p95 < 25 ms excluding database cold start.
- Dialog open with existing conversation: p95 < 250 ms excluding LLM calls.
- Auto-title generation: p95 < 2 seconds end-to-end, asynchronous and never on the chat reply critical path.
- Title model output: <= 32 tokens, one call per new conversation.

Cost controls:

- Default title generation to the same configured provider/model unless `ai-agent.conversation-title.model-id` is set.
- Allow hosts to use a cheaper model for title generation, but never for authorization decisions.
- Cache no title outputs across users or conversations.
- Store only the final title and compact audit metadata; avoid storing raw prompt context in audit rows.

## 5. Evaluation Strategy

Phase 12 evals are Java/Jmix-native. The merge gate should use JUnit 5, `@SpringBootTest`, `@UiTest`, Mockito/stubbed Spring AI calls, and existing fixture patterns. Live provider checks remain optional and tagged `@Tag("live")`.

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| Jmix view permission gate | Header button mount/visibility refresh | Apply `UiShowViewContext("AiAgent_ChatDialog")`; hide button if not permitted. |
| Surface enablement gate | UI init, navigation, direct route hit | Hide disabled menu/button; forward away from disabled full route with localized notification. |
| Single active fragment per tab | Navigation to `AiAgent_Chat` while header surface is enabled | Hide header button on the full chat route to avoid dual mount. |
| Title save race check | Before persisting generated title | Reload conversation with `UnconstrainedDataManager`; save only if title is still default. |
| Title sanitizer | Every generated title | Strip quotes/trailing period, cap 80 chars, reject blank/default/internal-vocabulary output. |
| Title failure isolation | Any exception in title generation | Audit `ERROR`, log WARN, keep existing title, never throw into chat path. |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|-------------------|-----------------------|
| Duplicate conversation rate during surface switch | 100% of TEST-14 failures and dogfood surface switches | Add fixture, inspect `AiChatSessionState` propagation and fragment detach behavior. |
| Unauthorized/disabled surface render | 100% of security test failures and admin dogfood reports | Fix `AiUiSettingsService`, `ChatSurfaceMounter`, or role policies before release. |
| Auto-title rejection rate | Sample all rejected title outputs during dogfood | Tune prompt/sanitizer; add rejected output to title fixtures. |
| Auto-title overwrite attempts | 100% audit/log review for race-test and dogfood manual edits | Fix reload-before-save path; release blocker if any overwrite occurs. |
| Dialog stale-handle incidents | 100% of UI test failures and structured logs for close listeners | Add close listener cleanup and regression fixture. |
| i18n missing-key reports | Every `I18nParityTest` run | Add missing keys to both root message bundles. |

## 7. Production Monitoring

**Tracing Tool:** Existing `AiToolCallAudit` + Micrometer/structured logs. Optional host-level external viewer: Arize Phoenix via OpenTelemetry if the host already runs it or explicitly asks for trace visualization.

**Key Metrics to Track:**

| Metric | Type | Labels | Alert Threshold |
|--------|------|--------|-----------------|
| `ai.agent.surface.settings.load.duration` | Timer | `outcome` | p95 > 50 ms for 15 min |
| `ai.agent.surface.button.visible` | Gauge | `surface`, `permitted`, `route` | unexpected zero for enabled/permitted header surface |
| `ai.agent.surface.switch.duplicate_conversation.count` | Counter | `from_surface`, `to_surface` | any non-zero |
| `ai.agent.dialog.open.count` | Counter | `outcome` | error rate > 2% |
| `ai.agent.dialog.stale_handle.count` | Counter | `route` | any non-zero in release candidate |
| `ai.agent.conversation_title.duration` | Timer | `model`, `locale`, `outcome` | p95 > 2 s or error rate > 5% |
| `ai.agent.conversation_title.rejected.count` | Counter | `reason` | spike > 3x baseline |
| `ai.agent.conversation_title.overwrite_skipped.count` | Counter | `locale` | monitor only; confirms race guard is active |
| `ai.agent.audit.write.failure.count` | Counter | `event_name` | any non-zero |

**Alert Thresholds:**

- Any duplicate conversation detected during a surface switch is a release blocker.
- Any unauthorized view/menu/button exposure is a P1 security defect.
- Title generation error rate above 5% for 15 minutes is P3; chat remains usable but operator audit should show the failures.
- Any auto-title overwrite of a manual edit is a P1 data-integrity defect.
- Any audit write failure on `conversation_title` is P2 because title cost/failure visibility is part of the operating contract.

**Smart Sampling Strategy:**

- 100% of conversations that switch surfaces during dogfood.
- 100% of title-generation failures and sanitizer rejections.
- 100% of skipped auto-title saves caused by non-default existing title for the first release window.
- 10% random sample of successful generated titles, stratified by locale.
- 100% of admin setting changes during dogfood, comparing saved settings to rendered surface behavior on next navigation.
