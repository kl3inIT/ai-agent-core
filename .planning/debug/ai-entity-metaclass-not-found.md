# Debug Session: ai-entity-metaclass-not-found

## Symptoms

- **Expected:** `./gradlew :jmix-app:bootRun` (postgres profile, `OPENROUTER_API_KEY` set) boots the app. Jmix's `MetaModelLoader` scans `com.vn.agent.entity.*` and registers a `MetaClass` for each; `sec_AnnotatedResourceRoleProvider` resolves `@EntityPolicy(entityClass = AiConversation.class)` references without error.
- **Actual:** Context refresh fails with `MetaClass not found for class com.vn.agent.entity.AiConversation` while `sec_AnnotatedResourceRoleProvider` instantiates. Earlier in the log, `MetaModelLoader` logged `WARN … Class com.vn.agent.entity.AiConversation is not loaded into metadata`.
- **Error type:** `IllegalArgumentException: MetaClass not found for class com.vn.agent.entity.AiConversation` wrapped in Spring's bean creation failure (bean `sec_AnnotatedResourceRoleProvider`).
- **Timeline:** Surfaced after `805c8a1`; underlying WARN predated the fix — issue was pre-existing, masked by the earlier bean-collision failure.
- **Reproduction:** `set -a; source .env; set +a; ./gradlew :jmix-app:bootRun` on `gsd/phase-07-flow-ui` at HEAD `805c8a1`.

## Current Focus

hypothesis: Stale `$JmixEntityEntry` inner classes in `ai-agent/ai-agent/build/classes/java/main/com/vn/agent/entity/` out of sync with the enhanced outer entity bytecode — Jmix's MetaModelLoader silently skips classes whose entity-entry contract is broken.
test: Inspect timestamps on `AiConversation.class` vs `AiConversation$JmixEntityEntry.class`; run a clean rebuild of the ai-agent module (forces re-enhancement) and retry bootRun.
expecting: Clean rebuild resolves the WARN and the downstream MetaClass error; app reaches `Started JmixAppApplication`.
next_action: resolved — see Resolution below.

- timestamp: 2026-04-21 — `JmixAppApplication` (host) has no `@EntityScan` and no `com.vn.agent` component scan override. **(Correct — not required; add-on is a proper Jmix module.)**
- timestamp: 2026-04-21 — Fresh bootRun log confirms Jmix module registration IS working: `Using Jmix modules: [io.jmix.core, ..., com.vn.agent, ..., com.vn.jmixapp]`. So the `@JmixModule` is picked up; the failure is downstream in `MetaModelLoader`.

- timestamp: 2026-04-21 — **Smoking gun:** `AiConversation.class` in `ai-agent/ai-agent/build/classes/java/main/com/vn/agent/entity/` had timestamp `Apr 21 20:25` while `AiConversation$JmixEntityEntry.class` (generated by the Jmix enhancer) had timestamp `Apr 21 18:03`. - timestamp: 2026-04-21 — After `./gradlew :ai-agent:ai-agent:clean :ai-agent:ai-agent:assemble :ai-agent:ai-agent-starter:clean :ai-agent:ai-agent-starter:assemble :ai-agent:ai-agent:publishToMavenLocal :ai-agent:ai-agent-starter:publishToMavenLocal` + `./gradlew :jmix-app:clean`, bootRun reaches `Started JmixAppApplication in 25.889 seconds` with **zero** `MetaClass not found` errors and **zero** `is not loaded into metadata` WARNs.

## Eliminated

- Missing `@JmixModule` on the host — ruled out: `JmixModulesProcessor` log shows `com.vn.agent` and `com.vn.jmixapp` both registered.
- Missing `@EntityScan` on `JmixAppApplication` — ruled out: Jmix Gradle plugin generates the persistence.xml with all add-on entities listed; JPA layer never complained.
- `persistence.xml` / `basePackages` mis-configuration in `AIConfiguration` — ruled out: module IS registered, entities ARE in persistence.xml; the issue was purely bytecode-enhancement drift.

## Resolution

**Root cause:** Stale `$JmixEntityEntry` inner classes in the ai-agent build output. The Jmix Gradle plugin's `enhance` task generates a `$JmixEntityEntry` inner class per `@JmixEntity` and weaves the outer class. When the outer entities are recompiled without a matching re-enhancement pass (can happen via IDE incremental builds or partial Gradle task graphs across a composite/multi-module workspace), the `$JmixEntityEntry` becomes inconsistent with the woven outer bytecode. `MetaModelLoader` then logs `WARN … is not loaded into metadata` and silently drops the entity from the Jmix meta-model, even though Jmix-module registration, persistence.xml, and EclipseLink weaving are all fine. Downstream, `AnnotatedResourceRoleProvider` dereferences `AiConversation.class` → `Metadata.getClass(...)` → `IllegalArgumentException: MetaClass not found`.

**Fix (applied):** Clean rebuild + republish of the ai-agent add-on so enhancement runs in lockstep with compilation, then clean jmix-app build cache:

```bash
./gradlew :ai-agent:ai-agent:clean :ai-agent:ai-agent:assemble \
          :ai-agent:ai-agent-starter:clean :ai-agent:ai-agent-starter:assemble \
          :ai-agent:ai-agent:publishToMavenLocal \
          :ai-agent:ai-agent-starter:publishToMavenLocal
./gradlew :jmix-app:clean
```

No source or configuration changes were made — this is a build-hygiene fix, not a code bug. Nothing to commit.

**Verification:** `./gradlew :jmix-app:bootRun` reaches `Started JmixAppApplication in 25.889 seconds` with zero MetaClass errors and zero `not loaded into metadata` warnings. Jmix-module registration log unchanged: `Using Jmix modules: [... com.vn.agent ...]`.

**Optional hardening (not applied; follow-up candidate):**
1. Document the clean-rebuild recipe in the project README / CONTRIBUTING under a "Jmix entity enhancement troubleshooting" note so future developers don't re-debug this.
2. Consider wiring `:jmix-app:bootRun` to depend on `:ai-agent:ai-agent:assemble` (with `outputs.upToDateWhen { false }` on the enhance task) to guarantee enhancement-before-run in a composite build. Trade-off: slower incremental runs. Defer until this recurs.
